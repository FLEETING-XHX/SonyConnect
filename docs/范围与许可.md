## 4. 耳机查询、写入与通知路径

T1/T2 为 **MDR V2 表 1/表 2**，并非 BLE/Classic 的同义词。先发现服务/协议族和表能力再选消息；未知设备不直接发送 V2 opcode。三态及特性也按实际回报子型选结构。C API 是可核对的参考接口，不代表首版已经选定原生库依赖：C# 复用/独立实现或 libmdr 包装由后续技术验证决定，并执行 L1/L2 署名义务。

`mdrHeadphonesGet*` 通常读取缓存，**不会自动线上查询**；`Set*` 通常暂存更改，须 `mdrHeadphonesRequestCommit` 才发命令。`RequestInit`/`RequestSync` 并不保证刷新所有高级设置，所需项要有显式 GET/回读；接收 `RET`/`NTFY` 后再更新确认状态。`mdrHeadphonesPoll` 提供语义事件；ACK/本地提交完成不等于耳机已经按要求生效。

下表列出固定源码已找到的具体路径；没有通知证据时明确写缺口。所有路径在本机未验证，不能保证该固件会回报/接受。来源缩写同时对应 §1 的固定代码入口。

## 7. 提示框与固定交互的实现验收约束

用户要求提示信息符合现有 UI。结合原说明 §14.2/14.5 与保留的中等版快照，后续实现采用以下约束，不修改本次静态快照：

- **形态与样式**：一般提醒使用设备行附近的紧凑提示浮层，操作结果可用同风格轻量 toast。沿用现有浅色背景 `#F8F9FC`、圆角、字体/字号及轻阴影，强调色沿用 `#7C88E4`；如需描边使用 1 px 细线。不得直接使用默认 `MessageBox` 或粗黑大弹窗。具体尺寸、圆角与停留时长在正式 UI 动态预览中核对，不在本文凭空定值。
- **固定 A 时短按 B**：保持 A 的最后确认状态，不发送切换/解锁命令；提示“请先右键解除当前设备固定”，可同时展示当前固定设备名称。提示不会替用户执行解除，也不增加二次确认步骤。
- **布局与操作**：提示不改变设备行、列表或窗口高度，不推移名称和下方组件；靠边时在工作区内避让，不遮住必需操作。重复触发合并为一个提示，不堆叠窗口或抢走焦点；保留其他无关控件操作。
- **真实结果**：处理中显示“正在锁定…”或“正在解除固定”，等成功确认及回读后才更新锁状态；失败保留最后确认状态，简短说明真实原因。未验证/不支持/超时分别表达，不统一写成“操作成功”。
- **可访问性与阶段**：文字配合图标，不只用颜色传达；键盘/屏幕阅读器能够得到等效提示，需关闭的浮层支持 Escape。简易 UI 阶段先验证结果和状态流程；进入正式 UI 时复用现有视觉并核对提示浮层、125%～200% DPI 和边缘位置。现阶段全部属于待实现、待验证要求。
