## 5. 交互草案：连接与状态

以下规则用于补充静态 UI 的行为，属于待实现草案；与用户后续明确指令冲突时，以新指令为准。

1. 启动后发现并识别已配对耳机；支持列表来自实际识别和能力查询，不凭型号名称猜测全部功能。
2. 连接中显示状态反馈。建立控制会话并读取当前设置后，才开放可用的耳机控件。
3. 未连接时禁用耳机设置，保留重新连接和软件设置入口。
4. 切换耳机时清空上一台的临时状态并重新读取；不能把上一台的 EQ 或模式自动写到新耳机。
5. 断开后取消待发送操作、标记读数失效。重新连接先回读真实设置，不默认覆盖手机端改动。
6. 耳机、电量、设置、播放状态发生变化时刷新 UI；避免用户必须关闭并重新打开窗口才能看到手机端操作结果。

### 设置写入与反馈

- 点击开关或模式后显示处理中；收到成功响应并回读一致后再视为操作完成。
- 失败时恢复最后一次确认值，并给出简短原因与重试入口。
- 滑块拖动时即时显示拟设置值；写入请求合并，避免每个鼠标像素都发送蓝牙指令。建议短时间合并连续输入，具体间隔经实测确定。
- 同一设置以最后一次用户输入为准；旧响应不能覆盖新输入。
- 切换设备、断开连接、退出时，不继续向旧会话发送排队设置。
- 同名功能在 WF / WH 系列上的命令和枚举需分别核对；未支持项明确禁用或隐藏。

## 6. 交互草案：主窗口

### 环境声音控制

- 三个模式互斥，最多只有一个选中。
- 通透选中时显示环境声音强度和关注语音控件。环境声音数值仅显示当前整数，最大档位显示“20”，不附带最大值分母。
- 降噪 / 关闭时，通透专用控件收起且不占布局空间；仅通透选中时显示。保留已确认的通透设置，窗口与后续内容联动变化，详见第 12 节。
- 切回通透后读取并展示耳机当前设置。
- 环境声音步长为整数档位；下限、关闭时行为和关注语音的组合关系需按协议验证。

### 耳机关机入口

- 电源图标按钮紧跟“已连接”文字，作为连接状态组的一部分；不把它用弹性空隙隔开。仅显示 16 × 16 的图标，无描边，背景与主界面一致（#F8F9FC），保留 24 × 24 点击区域。悬停提示“关闭耳机”。DSEE 开启时，DSEE Extreme 矢量字标贴近电量组左侧显示。详见第 18 节与第 19 节。

### 电量

- 左右耳和充电盒独立读取、独立显示。
- 不能把单一电量复制给左右耳或充电盒。
- 充电盒读数若无法持续刷新，应保留最后上报时间或过期状态；不要伪装为实时读数。
- 关盒、单耳使用、耳机充电和断开场景分别验证。

### 双设备与音源

- 多点连接开关表示耳机是否允许双设备连接。
- 关闭后隐藏设备列表与连接数量，保留设备列表区域的高度并居中显示“已关闭”；下方组件不向上补位，窗口高度不变。三种尺寸的关闭状态截图见第 2 节。
- 普通短按设备行表示选择耳机接收的音源，左侧圆点显示选择状态；固定播放成功后该圆点替换为扬声器＋锁图标。两者均不等同于 Windows 的默认输出设备。
- 固定播放使用长按设备行，解除固定使用右键单击带锁的设备行，不增加右侧三个点或通过二次菜单执行。1 px 浅蓝进度线沿逆时针围合，固定后的边框参考 Bluetooth 选中项，完整交互与处理中反馈见第 14 节。
- 选中另一台后，必须确认耳机音源状态实际变化，不能只改变圆点颜色。
- “双设备开关”“读取两个名称”“读取当前音源”“切换音源”分别验证，不视为一个已完成能力。
- 手机来电、电脑播放中切换、其中一台断开等场景需验证；本版不设计两路声音混音。

### Bluetooth 连接质量与当前编码

- 两项设置是耳机对 Bluetooth 连接的音质 / 稳定偏好；“声音质量优先”不代表固定使用某一个编码。
- **用户给出的动态状态示例：**
  - 选择“声音质量优先”，并正在接收手机声音时，当前编码为 **LHDC**。
  - 仍选择“声音质量优先”，切换到电脑作为当前音源时，当前编码为 **AAC**。
  - 选择“稳定连接优先”时，不论当前音源是手机还是电脑，当前编码均为 **AAC**。
- 双设备同时连接时，编码显示跟随耳机**当前正在接收的音源**。手机或电脑只是保持连接、但当前没有向耳机送音频的一方，不决定当前显示的编码。
- 用户选中另一设备后等待耳机的活动音源与 codec 状态更新；读取活动设备、偏好和 codec 均要分别验证，不能按设备名称硬编码显示。
- 没有实际活动音源时显示“等待播放”；协商状态读取失败时显示“未知”。不可保留旧设备的 LHDC / AAC 读数冒充实时值。
- 用户此前观察到手机端切换连接质量可能导致耳机重启；Windows 端要验证设置命令是否触发断开 / 重连、重连时长及控制会话恢复。真实经历不同则以耳机回读状态为准。

### 播放控制和系统音量

- 首先对接本机 Windows 系统媒体会话；仅显示会话实际提供的标题和来源。
- 没有媒体时显示“暂无播放内容”；不支持上一首 / 下一首的会话禁用对应按钮。
- 手机音源的播放信息和遥控能力独立验证，不默认与本机接口相通。
- 音量绑定当前耳机输出设备。系统快捷键、任务栏音量和软件滑块双向同步。
- 耳机不是当前输出设备或端点不可用时，避免误调其他扬声器。
- 静音状态、音乐音量和通话音量的对应关系需实测。

### 音压实验项

- UI 示例中的 41 dB 不是实测值。
- 必须确认数据来源、单位、刷新方式和适用音源后才显示真实数字。
- 不得将系统音量百分比、音频数字电平或 Windows 端点增益直接当作耳内音压。
- 数据不可用时显示“暂不支持”或隐藏该区域。

## 7. 交互草案：更多功能

### 标题与布局

- 窗口顶部标题为 `SonyConnect-更多功能`；内容区不再显示“更多功能”标题或 WF-1000XM5 型号，双栏设置从内容区顶部直接开始。当前中等版更多窗口为 680 × 772。
- 双栏布局：音质与通知提示在左，耳机控制、佩戴电源与软件设置在右。
- 更多功能使用独立窗口，关闭后回到主窗口；耳机设置建议即时提交。快捷键使用独立的草稿与保存流程，见第 16 节。
- 支持键盘焦点和窗口缩放。放大系统文字时不能裁掉控件；最终窗口尺寸以实际 Windows 渲染验收。

### 五段 EQ 和 CLEAR BASS

- 五个频段：400、1k、2.5k、6.3k、16k；不同耳机若返回不同能力，需单独适配。
- 五段和 BASS 的取值集合：−10、−9、…、0、…、+9、+10。
- 拖动、鼠标点击、键盘调整后都落到整数档位；不发送小数。
- 键盘方向键每次调整 1 档；端点处不能超出范围。
- 五段 EQ 不显示范围数字或独立刻度线，保留当前整数值与频率；2026-10-09 更新为 Wake Slider 的 20 格轨道，仍有 −10～+10 共 21 个整数取值，详见第 13 节。
- CLEAR BASS 独立放在下面，保留 −10、0、+10，减少垂直留白。
- 当前增益仅表示设备档位；协议未确认单位前，不在标签中擅自写成 dB。
- 预设列表从设备能力读取；自定义 1 / 2、手动和关闭的可用情况分别核对。
- EQ 开关若通过“关闭”预设实现，需保存并恢复上次有效预设；具体行为必须经实机验证。
- 保存后回读五段、低音和预设，确认实际写入而非仅本地显示。

### DSEE、触摸与模式循环

- DSEE 读取并写入设备当前设置；受连接模式等条件限制时明确提示不可用。
- 左右触摸功能仅提供设备允许的选项，不能在 UI 中任意组合未支持动作。
- **用户已确认（2026-10-09）**：本组控制左耳触摸功能分配为“环境声音控制”时的单击动作。每单击一次左耳耳机触摸板，耳机切到循环中的下一个声音模式。
- 三个可选模式为“降噪、通透、关闭”，**至少勾选 2 项，最多勾选全部 3 项**；共有下表四种合法组合。
- 这些复选项定义触摸循环的集合，不表示当前声音模式；当前模式仍由主窗口三选一按钮展示。

| 勾选集合 | 左耳连续单击的循环示例 |
| --- | --- |
| 降噪、通透、关闭 | 降噪 → 通透 → 关闭 → 降噪 → … |
| 降噪、通透 | 降噪 ↔ 通透 |
| 降噪、关闭 | 降噪 ↔ 关闭 |
| 通透、关闭 | 通透 ↔ 关闭；例如当前通透，单击后关闭，再单击回通透 |

- UI 必须阻止少于 2 项：只剩两项勾选时，这两项不能直接取消；未选中的第三项仍可勾选。要换成另一组两项，先勾上第三项，再取消不需要的项。
- 达到两项下限时保留勾选状态，并提示“至少选择 2 个模式”；不能先显示一项再等写入失败恢复，也不能静默自动替用户补选另一项。
- 左耳改分配为其他功能时，本组建议禁用并提示“将左耳设为环境声音控制后生效”，保留当前已确认的集合；切回环境声音控制时重新读取设备实际设置。禁用呈现方式为实现建议，具体联动需按设备能力适配。
- 修改集合只提交循环配置，不由 UI 额外发送当前声音模式切换；如果耳机自身因此调整了当前模式，应同步实际回报。
- 用户从主窗口选中了循环集合之外的模式后，下一次左耳单击进入哪一项，需实机核对；不能凭复选项顺序伪造耳机状态。
- 复选项写入成功后回读确认；失败恢复最后确认的合法集合。耳机左耳单击或手机端修改后，Windows 同步当前模式与集合，不重复发送同一动作。
- 左耳单击进入 / 离开通透时，主窗口环境声音与关注语音按第 12 节展开 / 收起。该规则与双设备关闭后保留占位区域无关。
- 需求层面不再把“至少 2 项、最多 3 项、左耳单击循环”列为未决定项；真实协议读写与机型兼容仍需实测。

验收：逐一验证四种合法组合；两项下限不能取消；三项可取消为任意两项；左耳单击跳过未勾选模式；手机端与主窗口状态同步；左耳改分配、写入失败及重连后仍按真实设置呈现。

### 智能免摘、摘下暂停和自动断电

- 各开关独立回读和写入。
- 智能免摘表示耳机自身 Speak-to-Chat；不等同于通话耳返，取消耳返不影响此项。
- 摘下暂停优先采用耳机内置策略；恢复播放行为不能仅依据开关名称推断。
- 自动断电具体条件与时间以设备能力为准，不虚构固定秒数。

### 通知与提示

- 通知 / 语音向导与音乐音量分开设置。
- 提示音量当前示例为 ±0；真实最小值、最大值和步长仍需核对，不沿用 EQ 的范围。
- 语言更换不纳入当前控件；本页不重新加入通话耳返。

### 软件设置与存储

- 开机启动只控制 SonyConnect 自身，不修改耳机设置。
- 开启“关闭窗口时最小化到托盘”后，关闭按钮隐藏窗口；托盘应有明确的退出入口。
- 关闭该选项后的关闭行为、Escape 与失焦是否隐藏，可在实现阶段确认。
- 托盘面板位置按现有 README 目标：所在显示器托盘附近，并避免越出可用屏幕。
- 自包含 EXE 是分发目标，不表示运行中不生成文件。设置建议存储在用户本地应用数据目录，具体路径和缓存策略在实现时记录。
- 本地偏好与耳机实际设置分开；启动和重连不自动恢复写入所有耳机参数。

- 主提示：“未连接 Sony 耳机”。

## 12. 主窗口声音模式与联动收起（SC-03 / SC-04 / SC-05）

新增日期：2026-10-08。用户要求在原主窗口左侧新增降噪状态，并解决通透子菜单消失后的空白与窗口突变。

### 已确认的状态要求

- 右侧保留原主窗口通透选中状态；左侧新增降噪选中状态，使用相同视觉样式与宽度。
- 环境声音强度和关注语音属于通透模式的二级菜单，**仅通透选中时出现**。
- 降噪或关闭选中时，整个二级菜单消失并释放布局空间，不能只设为透明或保留禁用控件占位。
- 子菜单收起后，其后的双设备、连接质量、播放器及底栏自然向上排列。
- 最终窗口高度按内容收紧，底部内边距保持不变；不把空白挪到窗口最下面。
- 原通透设置值仍需保留 / 回读。隐藏控件不等于重置环境声音或关注语音。

当前宽版静态设计测量（中等版与窄版见第 2 节）：

| 状态 | 宽度 | 高度 | 通透子菜单 |
| --- | --- | --- | --- |
| [通透主窗口](ui/主窗口-通透.png) | 480 | 841 | 展开 |
| [降噪主窗口](ui/主窗口-降噪.png) | 480 | 749 | 收起 |

当前高度差为 92，仅用于当前画布对照。实现时按字体、系统缩放、内容和实际布局测量，不硬编码这些高度。

### 推荐动效草案

这部分是解决用户所述突兀问题的实现建议；pen.dev 当前只展示两个最终静态状态，未实现真实窗口动画。

**采用同一时间轴协调子菜单收起、后续内容位移与窗口高度变化。**

| 对象 | 通透 → 降噪 / 关闭 | 降噪 / 关闭 → 通透 |
| --- | --- | --- |
| 模式按钮 | 显示已确认的目标模式 | 显示已确认的目标模式 |
| 二级菜单 | 先快速淡出，同时可见高度平滑减至 0 | 可见区域平滑展开，文字和控件短淡入 |
| 后续内容 | 与收起量同步上移 | 与展开量同步下移 |
| 窗口顶边（底边固定） | 随高度减小平滑下移 | 随高度增加平滑上移 |
| 底栏与内边距 | 跟随内容上移，保留原底部内边距 | 跟随内容下移，保留原底部内边距 |

- 鼠标切换建议约 200 ms 完成；可在 180～220 ms 内实测调整，采用平滑、无回弹的缓动。
- 子菜单淡出建议约 80～100 ms，尺寸与内容位移约 200 ms；不是等淡出结束才开始缩窗口。
- 展开时反向进行，可在展开开始后短暂延迟淡入，避免文字被狭小区域截得难读。
- 子菜单容器需包含其上下间距；收起后一起归零，不能留下单独的 gap 或 margin。
- 窗口高度联动过程中，控件、文字和图标保持原比例，不通过缩放整个窗口内容来伪装高度变化。Rubber Segment 选中背景自身的拉伸按第 13 节单独调节，不影响布局尺寸。
- 窗口宽度不变；最新锚点规则固定工作区右下角，模式栏以上区域保持窗口内相对位置，随窗口顶边平滑移动。

### 窗口位置与锚点

- 首次从托盘打开时，定位到当前显示器工作区右下角，不覆盖任务栏。
- **最新用户决定：主窗口固定右下角，模式切换时固定右边与底边，顶边随内容高度平滑移动。** 替代早期固定顶边建议；更多功能保持左侧底部对齐。
- 子菜单、内容布局、窗口高度与顶边位置使用同一时间轴；不在动画末尾再突然重新定位。
- 收紧后保持底栏与任务栏的原间距，不在窗口内部或底部新增空白；快捷键单开时顶部对齐，个性化同时打开时按第 17.2 节避让。
- 下次关闭后重新打开，可按当前状态的实际尺寸重新定位到托盘附近。
- 若屏幕工作区不足，先计算能够容纳目标状态的位置，再协调位置与高度；边界策略在多显示器和不同任务栏位置实测。

### 布局与实际窗口尺寸

- 动画开始前测量展开、收起两种状态的目标布局；动画中不要让自动尺寸机制提前直接跳到最终高度。
- 子菜单裁切区域、下方内容位置和原生窗口边界使用同一个进度，不能分别启动互不相关的动画。
- 可以短时使用内容位移与裁切配合窗口尺寸插值；动画结束后恢复正常自动布局，让最终高度继续由真实内容决定。
- 原生窗口调整确实涉及布局 / 绘制，必须在选定 Windows UI 框架中验证；静态设计无法证明其流畅度。
- 不固定为展开高度、不新增底部弹性占位、不先移内容再延迟缩窗口。

### 快速切换、失败和键盘行为

- 动画进行中再次切换，从当前高度、位置和透明度继续朝新目标过渡；不要先跳回旧起点。
- 不排队播放每一次点击动画，也不为了等待动效而阻塞蓝牙状态更新。
- 蓝牙写入中的请求有明确处理中反馈；失败时保持 / 恢复最后确认的模式，布局与最终确认状态一致。
- 降噪 ↔ 关闭不涉及通透子菜单，窗口高度保持不变，不重复执行展开 / 收起。
- 收起中的子菜单不继续接收点击或键盘焦点；焦点原在子菜单时移回模式按钮。
- 高频快捷键 / 键盘切换跳过位移动画，直接展示目标布局；用户关闭系统动画或要求减少动态效果时，同样采用直接布局切换或极短淡入淡出。
- 连接状态变化打断动效时，取消旧过渡并转向真实连接状态，不能让旧动画重新显示失效耳机控件。

### 验收场景

1. 通透 → 降噪、通透 → 关闭：子菜单彻底收起，后续内容上移，底部无额外空白。
2. 降噪 / 关闭 → 通透：恢复子菜单与当前真实值，窗口平滑展开，文字和滑块不被永久裁切。
3. 降噪 ↔ 关闭：高度不变。
4. 连续快速反复切换：不跳回起点、不堆积动画、不出现旧模式覆盖新模式。
5. 鼠标停在模式按钮上切换：按钮位置保持稳定。
6. 手机端更改模式、蓝牙写入失败、断开重连：最终模式与布局一致。
7. 100%、125%、150%、200% 系统缩放及放大文字：按实际高度测量，不能用当前 92 的高度差硬套。
8. 多显示器及不同任务栏位置：窗口不越出工作区，托盘打开和模式切换的锚点策略符合预期。
9. 键盘 / 减少动态效果模式：能够立即操作，隐藏子菜单不会接收焦点。

真实动画及上述场景尚未实现或验收。

### 13.2 环境声音模式：Rubber Segment

- `stretch` 的最终值尚未确认。后续预览应支持 0～100 连续调节，并提供 0、25、50、75、100 便捷对照；这些是预览取样值，不是五种固定产品模式。
- 官方参数中 `stretch = 0` 为普通滑动，增大后选中背景会在新旧位置之间伸展再收回。`squash`、`speed`、`glide` 和是否允许拖拽仍待调整，不默认锁定演示站数值。
- 拉伸只作用于选中背景；文字、图标、三段的布局宽度与点击区域保持稳定。
- 模式切换仍遵守第 12 节：仅通透展开环境声音强度和关注语音；窗口尺寸联动与选中背景动效分别调节，窗口底边不跟着橡皮效果回弹。
- 按下立即提供操作反馈，耳机写入未完成时标记处理中；成功并回读后才视为设置完成，失败回到最后确认状态。
- 连续切换应从当前视觉位置转向新目标，不逐个排队播放动画。外部手机 / 耳机状态变化按实际值同步，不重复发送设置命令。

参数依据：[React Bits Rubber Segment 官方说明](https://reactbits.dev/micro/rubber-segment)。

### 13.3 所有开关：Squish Switch

- 适用于多点连接、EQ、DSEE、智能免摘、摘下暂停、自动断电、通知 / 语音向导、开机启动、关闭到托盘等二态开关。
- `stretch = 0`：圆点移动过程中不随速度拉长或变窄。
- 用户要求的 **Hover scale = 0** 表示关闭悬停缩放。官方 `hoverScale` 属性为缩放倍率，代码应使用 **`hoverScale = 1`**；不得直接传入 0 把圆点缩没。若预览调节器使用“额外缩放量”，其 0 应映射到倍率 1。
- 保留开关圆点平移与开 / 关颜色反馈。轨道、圆点和标签的布局尺寸固定，不套用演示站默认的大尺寸。
- 速度与颜色过渡时长尚未指定，不因为选用 Squish Switch 就自动采用全部默认值。
- 复选框与设备音源单选框不因本条改成开关；本条仅统一已有二态开关的动效。
- 多点连接关闭成功后，按原规则在设备列表区域显示“已关闭”，下方组件与窗口高度不变；切换反馈不引起这一整块区域收缩。

参数依据：[React Bits Squish Switch 官方说明](https://reactbits.dev/micro/squish-switch)。

### 13.4 Bluetooth 连接质量：功能待定、Jelly Radio 去除挤压

- 暂保留“声音质量优先”“稳定连接优先”两个 UI 选项。用户报告手机端切换会让耳机重启；此处记录用户观察，尚未确认 Windows 端是否具有相同过程。
- 是否纳入实际功能，要先验证：能否读取及修改、是否触发重启 / 断连、是否自动重连、能否恢复控制会话并回读新设置。动效能做不代表控制能力已经验证。
- 两个按钮从切换开始到结束，宽度、高度、间距和文字 / 图标大小均不变；没有邻项被推开、选中项变大或未选项变小。
- 适配起点建议为 `swell = 0`、`barge = 0`、`shrink = 0`、`jelly = 0`、`bounce = 0`、`stagger = 0`，并检查组件内置悬停 / 按下缩放。最终以“全程固定大小、无挤压感”验收，不只检查参数名。
- 保留选中背景、描边、文字或图标颜色的短过渡；具体时长和层次在预览中调整。如果取消变形后组件仍不能满足固定尺寸要求，应改写动画层。
- 若实机验证会短暂断开，应显示“正在切换 / 正在重新连接”；不能在断开瞬间误判为永久未连接。超时或失败给出真实状态与重试入口，不显示虚假的成功选择。

参数依据：[React Bits Jelly Radio 官方说明](https://reactbits.dev/micro/jelly-radio)。

### 13.5 播放 / 暂停按钮：Codex 初稿建议

以下数值为设计建议，待用户看动态效果后确认。

- 保持圆形按钮外框和点击区域不变，播放三角与暂停双竖线在同一中心位置对齐。
- 鼠标按下时按钮视觉轻微缩至 0.97，释放后约 120 ms 恢复；没有旋转、果冻挤压或长回弹。
- 播放 / 暂停图标用约 140～160 ms 的淡入淡出切换，不让两个完整图标长时间重叠。第一版采用简单淡入淡出，暂不增加复杂形变。
- 按下反馈立即发生；显示的播放状态以媒体会话回报为准，动画完成不代表播放命令已经成功。
- 不添加持续跳动或呼吸效果。没有可控制媒体时禁用按钮；上一首 / 下一首沿用相同短按反馈，不做播放 / 暂停图标切换。
- 快速点击可打断当前过渡，最终图标与真实媒体状态一致。键盘操作直接更新状态，不播放缩放动效。

### 13.6 滑块：个性化样式与分档规则

**四类调节条可分别选择 Wake Slider 或 Elastic Slider，初始默认均为 Wake。** 音量条 `stepped = false`、连续调节；环境声音、五段 EQ 和 CLEAR BASS `stepped = true`、`stepSize = 1`。样式切换保持相同范围、当前值和功能，弹性 / 波动不产生额外数值。详见第 20 节。

**音量控制器的 Wake Slider 参数（2026-10-09 更新）：**

- `bars` 数量在 **35～45** 之间；当前静态预览采用 **40**，位于用户要求范围内。动态效果仍待原型验收。
- `sensitivity = 0.25`。
- 此前用户要求先记文档、不改画布；本次用户要求补齐缺项预览后，已将当前中等版 Wake 音量轨道同步为 40 bars。`sensitivity = 0.25` 是动态实现参数，静态图不代表已实现响应。
- 本条仅适用于音量控制器的 Wake 方案；环境声音、五段 EQ 与 CLEAR BASS 仍采用原先的 20 格规则。两种样式在个性化中可选，不要求四类调节条使用相同样式。

**环境声音强度：**

- Wake 样式使用 `bars = 20`、`max = 20`、`step = 1`，显示 20 格轨道与当前整数值；Elastic 样式也开启 `stepped`，整数步长 1。数值只显示当前数量（预览为 `20`），不显示“当前值 / 最大值”。
- `min` 仍需按设备能力确认。如果支持 0～20，就是 21 个值 / 20 个步进区间；如果有效值为 1～20，则为 20 档，不擅自添加第 0 档。格子数量不用于猜测协议下限。
- 最大值 20 必须能正常到达；20 格在最大值时全部点亮。只有通透状态显示该滑块与关注语音。

**五段 EQ 与 CLEAR BASS：**

- Wake 样式采用 20 格轨道，`min = -10`、`max = 10`、`step = 1`、`bars = 20`。Elastic 样式也开启 `stepped = true`、`stepSize = 1`；五段 EQ 与 BASS 在个性化中独立选择。
- **20 格是轨道分格数；−10～+10 仍为 21 个可选整数值、20 次步进。** 不得为了匹配格子数删掉 0 或任一端点。
- 第一版显示映射建议：−10 时亮 0 格，0 时亮 10 格，+10 时亮 20 格，亮格数为 `value + 10`；同时用数值明确显示当前增益，0 不等于关闭 EQ。
- 五段继续竖向排列，向上增大；CLEAR BASS 继续下置横向排列。需要检查 Wake Slider 源码并适配竖向输入、指针坐标及键盘方向，不假定官方提供竖向参数。
- 五段保留当前增益和频率，不显示 ±10 范围数字，也不额外添加刻度尺；20 格轨道是本次新增要求，替代早期连续轨道的表达。BASS 保留 −10、0、+10 与紧凑高度。
- 格子波动幅度和波及范围待预览，在控件自身空间内完成，不让相邻频段、BASS 或下方设置随动画移动。

**共同交互：**

- 数值即时跟随输入：音量条不启用 stepped，环境声音、五段 EQ 和 BASS 吸附到合法整数档位。视觉滞后不能推迟数值反馈或自行产生写入。
- 支持点击定位和方向键调整，分档控件逐档调整；边界不越界，拖出区域后仍能可靠结束操作。
- 蓝牙写入合并与回读遵守第 5 节；松手后发送最后拟设置值，设备返回与拟设置值不同则展示实际值并说明失败。
**更多功能 → 提示音量调整（SC-21，2026-10-09 用户确认）：**

- 使用 **Elastic Slider**，开启 **stepped**；`stepped = true`、`stepSize = 1`。
- 最小值 **−2**，最大值 **+2**；合法取值仅为 **−2、−1、0、+1、+2**，共 5 档。不允许小数，不把最大值 2 理解成 0～2。
- 拖动、点击定位和键盘调整均吸附到整数档位，端点不能越界。弹性仅作为视觉反馈，不能生成额外数值或写入。
- 这是提示音量的相对调整，独立于系统媒体音量、环境声音与 EQ，不套用它们的范围或格子数量。真实设备读写仍需实机验证。
- **2026-10-09 已按后续指令同步 pen 的宽、中等、窄三版更多功能页。** 静态轨道为连续圆角条，取消圆形手柄及圆点刻度，保留下方 −2、−1、0、+1、+2 数字标签，预览当前值为 0。节点记录 Elastic Slider、min = -2、max = 2、stepped = true、stepSize = 1；动态弹性与整数输入将在开发时实现。

参数依据：[Wake Slider 官方说明](https://reactbits.dev/micro/wake-slider)；音量条另一种可选样式：[Elastic Slider 官方页面](https://reactbits.dev/components/elastic-slider)。

### 13.7 更多功能下拉框：Glide Select

- 应用于 EQ 预设（用户称“模板”）、左右耳触摸功能及个性化窗口四个样式下拉框。样式选项均为“Wake 样式”“Elastic 样式”；模式循环复选项保留原控件类型。
- 触发后菜单从对应下拉框边缘展开；高亮背景在选项之间滑动。悬停只移动高亮，点击 / 键盘确认才提交选项。
- 官方参数 `popDuration` 控制菜单展开时长，`glideDuration` 控制高亮移动时长；具体值待预览，不自动把默认值当作最终决定。
- 菜单应覆盖在内容上层，不挤动下面的控件或改变窗口高度；靠近窗口底部时调整展开方向，长列表可滚动。

参数依据：[React Bits Glide Select 官方说明](https://reactbits.dev/micro/glide-select)。

### 13.8 动态预览与验收记录

- 先制作使用模拟数据的动态原型，再接真实耳机控制。模拟模式须明确标示，不能作为协议能力通过的证据。
- 当前后续预览以用户选定的中等版为准；宽、窄版的三尺寸比较记录保留在第 2 节，pen 不再维护对应页面。
- 每次确认记录组件、参数、窗口尺寸及是否定稿。Rubber Segment 的 stretch、调节条两种可选样式、播放按钮初稿、Jelly Radio 去形变效果与 Glide Select 的速度是本轮待比较项。
- 保留操作中再次输入的响应能力，不为播放动画锁住所有控件；旧回调不能覆盖最新目标状态。
- 减少动态效果时移除拉伸、波动、弹性和缩放，保留即时状态 / 短颜色反馈。键盘操作不播放装饰性位移动画。
- 最终检查真实状态同步、失败回退、断开重连、连续操作和系统缩放；动效的结束时间不作为耳机命令成功的判断依据。

## 14. 双设备固定播放与长按交互（SC-07 / SC-26）

新增日期：2026-10-09。依据用户提供的手机 App 截图与使用描述：设备菜单中存在“固定播放设备 / 解除固定”和“断开”等操作；普通选择 A 作为当前音源后，B 开始播放仍可能让 A 的视频 / 音乐暂停并抢占耳机音源。因此用户确认需要保留独立的“固定播放设备”功能。

### 14.1 普通选择与固定播放

- **普通选择**：短按设备行，选择当前收听的设备；这不表示已经固定，也不承诺其他设备不能抢占。
- **固定播放**：对指定设备执行长按确认，目标是保持收听该设备，避免另一台设备普通媒体播放抢占。
- 固定对象是耳机已连接设备的稳定身份，不是显示名称、列表序号或 Windows 默认音频端点。设备改名或列表重排后不能固定错对象。
- 每次只允许一个固定设备。当前音源、固定目标与连接状态分别读取；不能仅因检测到某台正在播放就把它显示为固定。
- 用户目标针对双设备媒体播放竞争；来电、语音助手、系统提示等优先级，以及另一台应用是否暂停，均需按耳机实际行为验证，不推断固定可阻止所有声音中断。

### 14.2 用户已确认的操作与视觉

- 不在设备名称右侧新增三个点，也不通过二次菜单执行固定。长按目标设备整行作为固定入口，左侧状态区域也属于该行的点击区域。
- 参考 [React Bits Fuse Button](https://reactbits.dev/micro/fuse-button) 的长按确认方向，边框轨迹按 SonyConnect 要求定制；本节不假定官方组件已原生支持全部所需方向与形状参数。
- 鼠标持续按住时，沿设备行外围**逆时针**显示长按倒计时进度。进度线采用 Bluetooth 选中项同款浅蓝色 `#7C88E4`、1 px 宽度，不用粗深蓝描边。
- 线条随按住时间逐步延伸，最后围成完整的**圆角矩形边框**；沿用设备行形状，不绘制立体长方体，不扩宽或挤压该行。
- 边框围合代表长按确认动作完成，随即提交固定命令；收到成功响应并回读后，完整浅蓝细描边作为固定状态保留，左侧小圆点替换为**扬声器＋锁**组合图标。
- 长按完成但耳机尚未确认时显示“正在锁定…”，不得提前用锁图标宣称固定成功。失败恢复最后确认的状态，并显示简短原因。
- 图标替换使用预留的固定宽度区域，不推移设备名称。右侧状态文字建议改为“已固定”，配合图标说明，避免只靠颜色表达。
- 整个长按、提交与固定过程都不改变设备行高度、列表高度、下方组件位置或窗口高度。

### 14.3 待预览参数与取消行为

以下数值和起点属于初稿建议，尚未由用户定稿。

| 项目 | 建议 / 待确认内容 |
| --- | --- |
| 长按总时长 | 先试 1000 ms，再比较约 800～1200 ms；不能直接把参考组件默认值作为最终决定 |
| 轨迹起点 | 先试顶部中点，沿顶部向左 → 左边向下 → 底部向右 → 右边向上，最后回到起点 |
| 进度速度 | 按实际持续按住的时间匀速推进，完成前不能因缓动看起来提前围合 |
| 线条颜色 | 使用当前主题中比普通选中描边更深的同色系颜色，具体色值与线宽待预览 |
| 提前取消 | 长按未完成就松手、移出有效区域、按 Escape、窗口失焦或收到 pointercancel，取消本次固定并重置进度 |
| 取消收尾 | 建议约 120～160 ms 撤去未完成的线条；不保留进度供下一次接着按 |

- 短按与长按必须由同一套手势判定协调。普通短按在释放后执行音源切换；已进入长按的手势未完成就释放，仅取消固定，不补发一次短按切换。
- 短按判定阈值待动态预览确定。进度开始显示不能立即剥夺正常短按，按下本身也不能先发音源切换再判定长按。
- 长按达到阈值只触发一次固定命令；继续按住或松开不会再次触发，也不追加普通 click 操作。
- 提交固定期间锁住同一固定操作的重复发送；其他无关控件不必全部禁用。
- 持续时长使用实际时间计算，不能按动画帧数累计。窗口失焦或挂起后取消手势，不能恢复时直接补满倒计时并发送命令。
- 减少动态效果时，可用静态边框加剩余时间 / 进度文本表达长按过程，保留必要的确认时长；避免取消动效后变成单击就固定。
- 键盘替代方案建议为设备行聚焦后按住 Space，Escape 取消；其阈值与鼠标一致，避免按键自动重复导致多次提交。边框运动可省略，需保留进度与状态反馈；最终按键方案待确认。

### 14.4 状态与反馈

| 状态 | 设备行显示 | 可执行动作 / 后续 |
| --- | --- | --- |
| 未选中、未固定 | 普通行、空圆点、“已连接” | 短按选为音源；长按请求固定该设备 |
| 当前音源、未固定 | 普通选中背景与圆点、“正在接收声音” | 长按请求固定；另一台普通播放仍可能抢占 |
| 长按进行中 | 保留原状态，增加逆时针浅蓝细进度线 | 提前取消不改设备状态；到达阈值提交一次 |
| 固定提交中 | 完整细描边、“正在锁定…”，尚无已固定锁图标 | 等待响应并回读；失败恢复原状态 |
| 固定成功 | 完整浅蓝细描边、左侧扬声器＋锁、“已固定” | 右键设备行解除固定；持续读取实际状态 |
| 解除固定提交中 | 保留已确认锁与边框、“正在解除固定” | 等待回读；成功恢复普通状态，失败保留固定 |
| 固定失败 / 超时 | 恢复最后确认的音源与固定状态，给出简短失败提示 | 允许重新操作，不假定目标已经锁定 |
| 固定目标断开 / 多点关闭 | 取消进行中的手势，不保留失效设备为正在播放 | 重新读取固定状态；多点关闭时沿用“已关闭”占位区域 |

固定后的边框是持续状态标识；长按中的逐步围合是暂时进度，两者必须能从文字与图标区分。

### 14.5 右键解除固定与切换固定目标

- **用户已确认：右键单击带锁的设备行，直接解除该设备固定。** 整行包含锁图标均为有效右键区域，不弹出二次菜单，不要求长按，不再使用“再次长按解除”的方案。
- 右键立即提交解除固定命令，并显示“正在解除固定”；等待期间保留最后确认的锁图标与边框。成功并回读后去掉锁和固定边框，恢复实际普通音源状态；失败保留原固定状态并显示简短原因，不伪装为已经解除。
- 右键操作不触发普通音源切换，不重播长按倒计时，不暂停或播放媒体。重复右键不重复发送正在处理的解除命令；未带锁的设备不执行解除固定。
- 悬停带锁设备行时提示“右键解除固定”。已固定行再次左键长按不执行解除，保持当前固定状态。
- 已固定 A 时，普通短按 B 的行为尚未确认。建议先保留 A 的固定并提示“当前已固定 A”，不静默解除固定；需要另行确认是否允许普通短按直接改音源。
- 已固定 A 时长按 B，建议视为“将固定目标改为 B”。若协议支持直接更换，优先一次完成；若必须先解锁 A 再固定 B，需要明确中间状态，并在第二步失败时回读实际结果，不能仍显示 A 已固定。
- 右键解除固定已确定；本节中固定状态下短按另一台、长按改固定目标的行为仍属建议，需后续确认。长按固定的时长和边框起点也仍待预览。
- 键盘解除固定入口仍待设计，应提供与右键等效的可访问操作，不把已记录的 Space 长按固定自动复用为解除。

### 14.6 协议验证与断开连接入口

- 固定功能列入需求，但需要分别验证读取固定目标、设置目标、解除固定、从手机 / 耳机同步状态及跨重连行为。SC-07 的普通音源切换通过，不代表 SC-26 固定播放也通过。
- 对非当前音源长按固定时，需验证设置固定是否同时切换音源；若需要独立切换步骤，应在同一次操作中明确协调并回读，不只给非活动设备加锁图标。
- 若协议尚不可用，只能在标明模拟状态的原型里演示。不能通过本机静音、强行暂停另一台应用或只修改 UI 来冒充耳机固定功能。
- 重连后读取耳机实际固定目标；不凭本地上次选择自动重写。关闭双设备功能或目标断开后，耳机是否保留固定偏好需实测。
- 截图中的“断开”操作记录为后续入口设计与能力验证事项，本轮用户明确的是长按固定，尚未指定断开操作手势；不能把长按解释为断开连接。
- 截图里的“取消注册”不因出现在参考图中自动加入本轮需求。

### 14.7 验收场景

1. 短按 A：正常切换当前音源，不出现锁；普通选择与固定有明确区别。
2. 长按不足时长：进度取消，不固定，也不额外切换音源。
3. 持续长按到围合：只提交一次；回读成功后显示扬声器＋锁与完整边框。
4. 固定 A 后 B 开始播放：验证耳机实际仍收听 A；记录双方播放器行为，不仅检查 UI 图标。
5. 非当前音源 B 被长按固定、已有固定目标时改固定目标：验证音源与固定目标正确同步。
6. 命令失败 / 超时、目标断开、窗口失焦、快速反复按住：不出现假锁定或重复发送。
7. 手机端固定 / 解除固定：Windows 自动同步，外部变化不触发重复写入。
8. 右键带锁设备行：只提交解除固定，不弹菜单、不触发音源切换、不执行长按倒计时；成功后恢复正常多点竞争规则，失败保留锁。
9. 右键未固定设备、重复右键、在已固定设备上再次左键长按：不误解除、不错发音源切换、不重复提交。
10. 宽、中等、窄三版及系统缩放：边框完整、逆时针方向一致，图标不挤压文字，列表与窗口尺寸稳定。

当前 pen 已新增长按逆时针进度、正在锁定、固定播放及正在解除四个完整主窗口预览（第 22.1 节）。边框统一参考 Bluetooth 已选项：`#7C88E4`、1 px，背景 `#EEF0FD`；扬声器＋锁与“已固定”文字共同表达成功状态。真实固定命令、状态读取与防抢占效果均尚未实测。

## 15. 媒体占位符、版本底栏与软件更新（SC-09 / SC-22 / SC-27）

### 16.5 右 Ctrl 默认键位（2026-10-09 用户确认）

- 降噪：**R-Ctrl+F1**；通透：**R-Ctrl+F2**；关闭：**R-Ctrl+F3**。Reset 恢复这三组草稿，自定义、保存及失败回退规则不变。
- R-Ctrl 指右 Ctrl。录入、比较、显示与保存都保留修饰键的左右侧；左 Ctrl+F1～F3 不触发。长按导致的重复事件不连续写入耳机。
- Windows 定义 VK_RCONTROL / VK_LCONTROL，但 RegisterHotKey 的 MOD_CONTROL 匹配任意 Ctrl，不能直接满足限定右侧的要求。实现时需要按键事件 / 低级键盘钩子等可区分左右侧的路径；不要只注册普通 Ctrl 后在回调丢弃左侧通知，因为还需要保留左侧组合对前台应用的正常输入。
- 普通不限定左右的组合可用 RegisterHotKey；指定右 Ctrl 的路径分别验证前台、托盘、录入暂停、退出释放、组合键冲突与响应延迟。钩子中只做轻量识别，把耳机命令交给异步处理，不在输入回调里等待蓝牙响应。
- Fn 不作为默认修饰键。其行为依键盘 / 驱动而异，不能假设 Windows 应用总能收到独立 Fn 事件。
- pen 的快捷键入口、默认编辑、录入与冲突状态、Reset 元数据已同步右 Ctrl。冲突预览故意让降噪与通透使用相同 R-Ctrl+F1，仍是待修正草稿。

依据：[Windows 虚拟键码](https://learn.microsoft.com/en-us/windows/win32/inputdev/virtual-key-codes)、[RegisterHotKey 修饰键语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。当前是实现约定，不代表全局快捷键已开发。

5. 稳定连接优先，确认 LDAC 不可用，并分别回读实际编码；不能预设两台均为 AAC。
6. 手机和电脑同时连接、没有播放、切换偏好后重连、读数失败：当前音源和 codec 状态一致，无旧值残留。

以上 DSEE 遥控、编码查询及连接质量切换仍需按型号实机验证；本轮完成的是状态展示设计和交互记录。

## 21. UI 检查与设备类型图标（2026-10-09）

### 21.1 PC / 移动设备自动识别

当前 pen 设备行已经分别使用电脑（monitor）与手机（smartphone）图标，但这些只是静态示例，未接入自动识别。

可实现路径已找到：项目中的 SonyHeadphonesClient 底层协议定义了带 `bluetoothClassOfDevice` 的设备列表，也存在不带该字段的列表版本。应按耳机能力选择查询，不能假设所有型号都会返回类型。

- 类型为 Computer 时显示电脑图标；类型为 Phone 时显示手机图标。蓝牙类别不能完全等同于真实外形，例如平板可能上报 Computer；不承诺精确识别所有移动设备。
- 优先使用耳机返回的“连接源设备”类型。不要使用耳机本身的 ClassOfDevice 来判断电脑 / 手机。
- Windows 已知设备的类型可作为补充，但手机连接耳机不等于手机已与电脑配对，不能仅靠 Windows 的已配对列表覆盖耳机的全部音源。
- 类型缺失 / 未分类时使用通用设备图标；不根据设备名称、厂商品牌或列表顺序强行判断。手动指定图标属于可选建议，尚未增加设置入口。
- 图标类型与当前音源 / 固定状态分别呈现，电脑 / 手机图标仍保留；左侧圆点在固定成功后换为扬声器＋锁。图标替换不推移名称。
- 设备身份采用协议提供的稳定标识，类型随该设备缓存；改名、列表重排及重连不能把图标套到另一台设备。

本地源码证据：
- `references/SonyHeadphonesClient/libmdr/include/mdr/ProtocolV2T2.hpp:1546`：24 位 `bluetoothClassOfDevice`；附近另有不含类型字段的结构。
- `references/SonyHeadphonesClient/libmdr/src/HeadphonesV2.cpp:124`：查询带蓝牙类别的配对设备管理能力。
- `references/SonyHeadphonesClient/libmdr/src/HeadphonesV2T2.cpp:187`：解码带类型的列表，但当前只向内部设备状态复制地址、名称、连接与播放状态。
- `references/SonyHeadphonesClient/libmdr/include/mdr-c/Headphones.h:358`：当前公开的 MDRPairedDevice 不包含类型字段。实现时需补齐底层状态与接口的透传，不能误认为 UI 已可直接读取。

类别说明来源：[Microsoft BluetoothMajorClass](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothmajorclass?view=winrt-26100)；Windows 接口：[BluetoothDevice.ClassOfDevice](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothdevice.classofdevice?view=winrt-26100)。字段存在是实现依据，WF / WH 实机返回值仍待验证。

### 21.3 编码记录核对

Sony WF-1000XM5 的 Classic Audio 支持 **SBC / AAC / LDAC**；LE Audio 使用 LC3，本版仍按用户要求只展示两个连接质量偏好。稳定连接优先时不能使用 LDAC，不能据此断言所有设备都使用 AAC。[Sony 支持的编解码器](https://helpguide.sony.net/mdr/2963/v1/en/contents/TP1000781984.html)

用户已纠正此前手机“LHDC”为 **LDAC**。另外，高通的系列是 **aptX**，LHDC 来自 Savitech；这些名称仅用于澄清，不给 WF-1000XM5 增加未支持的编码选项。[Qualcomm aptX](https://www.qualcomm.com/audio/technologies/aptx)、[Savitech LHDC](https://lhdc.savitech.co/)

用户观察：多数手机在连接稳定性优先时使用 AAC；在手机蓝牙设置里关闭 AAC 音质后会使用 SBC，官方手机 App 也能显示 SBC。已记录此场景并新增稳定优先 / SBC 预览；具体结果依设备、系统、设置与实际协商而定，不将其写成所有手机的强制规律。Sony 指南确认官方 App 可以查看当前 codec。[Sony 编码查看说明](https://helpguide.sony.net/mdr/2963/v1/en/contents/TP1000781965.html)

当前活动音源为电脑时可以显示 AAC，为移动设备且实际协商为 LDAC 时显示 LDAC，也需正确显示 SBC。**设备类型图标不能用来推断 codec**；无法读取时显示未知，未播放显示等待播放。UI 不新增“在 Windows 强制关闭手机 AAC”的开关。
