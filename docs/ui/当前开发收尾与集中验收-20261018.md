预设本地预算：隐藏 CPU ≤2%、可见空闲 ≤5%（均以单逻辑核 100% 计）、私有内存 ≤256 MiB；第二批生命周期 GDI/USER 增量 ≤4、内核句柄增量 ≤16。预算在首次采样前声明，未为通过而放宽。空载探针开销单独记录，报告 CPU 是含探针的原始值，没有用扣减后的数值代替。

### 定位与修复

1. 初次每 250ms 枚举全系统线程和短周期消息唤醒给结果带来明显开销；改为阶段边界枚举、等待实际消息。初始失败 JSON 保留，不将它误报为产品空闲 CPU。
2. 之后两批窗口创建/销毁仍各增长约 40 个内核句柄。PSS 显示 Mutant 与 Section 各每次增长一个；正常桌面权限下也复现，排除仅为沙箱现象。
3. 最小组件对比：第二批 20 个独立 Painter 增长 40 个句柄，而同一工厂创建 20 个 DC 绘制目标仅有初始少量增长。依据该证据，修改 `main_window.cpp` 的 Painter：同一 UI 线程内存活窗口共享 Direct2D 工厂，使用线程局部弱引用；最后一个 Painter 销毁时释放，不把 COM 工厂留到退出公寓以后。
4. 未改变协议、控制器、设备状态或动画提交策略。绘制目标、画刷、文字布局和每个窗口的图像缓冲仍独立。

最终本地基线通过；第二批 20 次窗口创建/销毁的内核句柄、GDI、USER 最终增量均为 0，总计 40 次循环，分发动作数为 0。最终各阶段峰值私有内存均低于 65 MiB。修复前同类双窗口阶段约 80 MiB、75 线程，修复后约 63 MiB、40 线程；这是本次环境的观测，不能外推成所有设备的性能承诺。CPU 原始阶段数据见 JSON，不将不同采样实现的 CPU 值直接作为产品优化对比。
