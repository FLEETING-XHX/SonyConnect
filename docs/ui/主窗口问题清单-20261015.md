## 1、2、8：位置与窗口高度

### 用户反馈

- 首次打开应在屏幕右下角。
- 通透切回关闭或降噪时，当前效果是固定窗口顶部、底部向上截短，且没有平滑动画。
- 断线切到小窗口时，窗口仍留在上方。

### 已核对的实现

`main_window.cpp` 创建窗口时使用 `(100,100)`；`resize()` 在 720、822、232 的内容高度间直接设置大小，保留旧 `left/top` 再限制到工作区。当前没有初次右下定位，也没有窗口高度插值。`ready` 或声音模式变化会触发同一 `resize()` 路径。

### 修复要求

- 初次展示按目标显示器 `rcWork` 定位，包含任务栏占位、DPI 和统一外边距。
- 状态导致高度变化时，保持当前窗口底边稳定，顶部随高度变化；不能把它误实现为每次刷新都重新吸附右下角。
- 保留用户拖动窗口位置的能力。用户移动后的尺寸过渡围绕移动后的底边进行，防止覆盖用户的位置选择。
- 窗口外框、通透内容区展开/收起和其他控件位移采用统一进度；可打断、反向，不闪空白、不先裁切后跳变。
- 连接、断开、失败、重连均使用同一套规则，避免小窗口留在旧的大窗口顶部。
- 高 DPI 或工作区不足时保留内部滚动方案；不恢复最大化、全屏或边缘拉伸。

验收：100% / 150% / 200% DPI，任务栏不同位置、多显示器、首次启动、用户拖动后切换、连续切换和切换中断线。动画时长先以实际观感校准，不把建议时长写成硬件承诺。

## 3：WakeSlider 与实时百分比

### 当前差异

现有 `draw_slider()` 以当前位置画一个对称凸起，没有拖动速度、方向、速度滤波、弹簧跟随或松手后的自然回落。焦点绘制分支还会覆盖已画出的波峰。拖动消息更新条形自身，但百分比画在父窗口上，没有在同一输入帧明确重绘。

### 用户指定配置（原样记录）

```tsx
<WakeSlider
  defaultValue={50}
  min={0}
  max={100}
  step={1}
  bars={32}
  height={24}
  restHeight={12}
  gap={4}
  fillColor="#f5f5f5"
  trackColor="#27272a"
  sensitivity={0.25}
  reach={5}
  skew={0.6}
  glide={0.25}
  smoothing={100}
  showValue
  onChange={value => console.log('value', value)}
/>
```

官方参考：[WakeSlider 页面](https://reactbits.dev/micro/wake-slider)、[用户指定注册表](https://reactbits.dev/r/WakeSlider-TS-TW.json)。源码及依赖 JSON 已保存到反馈附件目录。

用户示例的外层容器宽度为 320，导入为 `import WakeSlider from './WakeSlider'`。这两项一并保留为参考；原生界面的实际占位按 Pen 适配，初始数值读取系统真实音量，不把示例的 50 当作设备读数。

源码核对：位置通过弹簧跟随目标，速度另行平滑；速度决定波峰高度和作用范围，方向决定前后不对称的拖尾；静止后回落。它不是把某个格子固定画高。注册表列出的依赖为 `motion@^12.23.12`。

### 原生实现要求

- 在当前 C++ / Direct2D 绘制层适配动效算法，不在 CMake 工程执行 `npx shadcn` 或添加 React/Tailwind 运行时。
- 32 格、0–100、整数步长用于系统音量；如果环境声音共用动效内核，仍保留 Pen 的 20 档及设备实际范围。
- 音量百分比、填充和输入目标值同帧更新，不等松手、不等系统端点确认；拖动期间旧通知不能把数值拉回。
- 系统音量写入继续合并末值，避免每个动画帧都入队。松手提交最终值，失败需反馈并恢复可信读数。
- 外部音量变化在未拖动时继续同步；键盘操作也实时更新数值。焦点样式不得覆盖波峰。
- 尊重系统减少动画设置；停止交互并回落后停止动画定时绘制。
- 上述深色 `fillColor/trackColor` 是用户提供的参考配置，先完整保存；应用的颜色与字号应与第 4 项 Pen 精确复刻要求统一，不擅自把整个浅色窗口改成深色主题。

验收：慢拖、快拖、反向、停住、松手、键盘、外部系统音量变更，观察波形、填充与百分比；必要时用录像验证连续过程，单张截图不能证明动画正确。

## 4：图标、字体与 Pen 一致

当前原生 `Painter::icon()` 使用直线、圆形与矩形近似画图标，不是 Pen 中 Lucide 图标的原始几何；原生字体为 Microsoft YaHei UI，Pen 主要为 Noto Sans SC。因此首版截图相似不能称为完美复刻。

修复时逐项核对耳机、通透、关闭、声波、电脑/手机、蓝牙、媒体、音量、更多箭头、充电盒和锁的原始路径、尺寸、线宽、圆角和颜色。保留用户选定的银白应用 ICO，主窗口标题栏仍不添加 Logo。

字体核对包含字体来源、可用性、字重、字号与回退方式；如需随程序分发字体，先确认字体许可及包体成本。不能简单把当前字体名称换成一个未安装字体后宣称一致。

验收以最新 Pen、相同状态及相同 DPI 截图逐项对照，不用旧导出稿作唯一依据。

## 5：确认速度与状态反馈

用户截图中多次出现“耳机回读确认”“已有操作在等待确认”，需优化等待体感，但当前没有可量化的实机耗时结果。

只读核对结果：

- 工作任务使用单线程 FIFO，前台操作可能排在已有后台读取之后。
- 普通 ANC 使用写入、回读、目标值匹配路径，没有固定的 `sleep`。
- Multipoint 另有最多 500 ms 的提示等待；在收到需确认的提示并确认后，另有 300 ms 等待，再查询开关、音源列表和编码。不能把这两项套用到所有 ANC 操作。
- UI 中途快照每 500 ms 更新，任务完成会立即投递完成消息，不能笼统认定每次都额外等 500 ms。
- 现有全局 busy 会禁用所有耳机操作，并把普通操作的等待显示在连接状态处，容易把“设置未确认”与“连接状态”混淆。

先记录点击、入队、实际发送、ACK、有效回读、UI 呈现六个时间点，再区分排队、设备响应与绘制延迟。

优先改进：点击立即反馈；保持“已连接”，在相关设置旁标注提交/确认状态；目标动画与已确认值分离，失败回到真实值。动画与发送并行，不能等动画播完才开始设备操作。

不得用跳过回读、把 ACK 当作参数确认或无依据缩短超时来制造“变快”。若实测表明必须调整会话调度、并发或底层等待策略，按项目规则先说明原因和影响范围再实施。

验收必须比较同一设备/固件的优化前后分段耗时，覆盖失败、拒绝、超时和通知回退；不能只展示成功动画。

## 6：ANC 模式切换动画

当前三个模式按 `selected` 直接切换背景和文字，没有连续的选中块过渡。

用户指定参考配置：

```tsx
<RubberSegment
  items={['Day', 'Week', 'Month', 'Year']}
  defaultValue="Week"
  onChange={(value, index) => console.log(value, index)}
  trackColor="#27272a"
  thumbColor="#fafafa"
  textColor="#fafafa"
  activeTextColor="#18181b"
  size="md"
  radius={10}
  inset={3}
  equalSlots
  stretch={0}
  squash={3}
  speed={1}
  glide={0}
  draggable={false}
/>
```

官方参考：[RubberSegment 页面](https://reactbits.dev/micro/rubber-segment)、[对应 TS-TW 注册表](https://reactbits.dev/r/RubberSegment-TS-TW.json)。已保存完整 JSON，依赖为 `motion@^12.23.12`。源码包含边缘弹簧落位与压缩回弹；`stretch=0` 不代表关闭所有动画。

在本程序中将演示选项映射为“降噪 / 通透 / 关闭”，初始值来自耳机真实状态，不使用示例中的 Week 或硬编码某个模式。保留 `draggable=false`，点击与键盘仍可选择。外观颜色使用 Pen 对应样式，动画采用用户指定参数进行原生适配。

验收：相邻/跨项切换、连续点击、键盘、设备外部通知、回读拒绝或失败的回退；与第 2 项高度过渡同步，但绝不能把动画完成当作耳机确认成功。

## 7：音源长按围合、确认与锁位置

当前只有设备行底部的 2 px 直线进度，锁画在靠右的状态文字区域。

Pen 对照：11 号 `mAFdz` 的 `wuxoj` 是逆时针的圆角矩形围合；13 号 `NWLYt` 左侧 `i6jv2` 为扬声器和右下小锁的组合。对应尺寸以当前 Pen 的节点为准：围合框约 `(1,1,410,38)`，左侧状态组合约 `(12,12,16,16)`。

修复要求：按住 1 秒逆时针围合，松开未满时取消；完整围合后显示“正在锁定”，耳机确认后才显示“已固定播放”与正确位置的小锁。保留移出、失焦、Esc、会话变化等取消规则和右键解除。不能在进度到 100% 时提前显示锁定成功。

验收覆盖鼠标与键盘、提前松开、移出、失焦、断线、设备拒绝、正在解除和解除成功，并与 Pen 11–14 号状态逐一比对。

## 9：关闭双设备后当前设备消失

截图 7 显示关闭开关后为 `0 / 2`、两个“等待设备连接”占位；用户反馈当前 PC 实际仍在连接。该现象按功能错误优先处理。

当前不能认定代码是因开关为 false 而主动隐藏所有设备：主窗口按 `connection_slot != 0` 过滤并计数，并没有该开关为 false 就清空的分支。会话层切换后重读列表，回读列表会替换旧数据，超出已报告能力的列表会被拒绝/清空。

需结合真实日志区分：空回读、slot 全为 0、能力校验失败、切换期间状态尚未完整、后续通知覆盖等。以上是待核实方向，不是已确认的耳机协议行为。

修复要求：

- 区分“未连接”“正在刷新”“耳机未提供音源列表”，未知不显示为确定的零连接。
- 刷新期间如保留旧记录，明确标“上次连接”，不得伪装为当前已连接。
- 当前设备名称与连接状态使用可信来源。Windows 本机连接信息若作为辅助，需与 MDR 回读音源列表分开，不凭名称构造协议连接记录。
- 单设备模式按 Pen 收起第二槽位时，不能连当前设备也丢失；恢复双设备后正确显示真实列表。

验收：开启→关闭→再次开启，覆盖仅 PC、PC+手机、播放/暂停及切换中断线，检查列表、slot、active source 与界面状态一致。
