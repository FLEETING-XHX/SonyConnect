## 开发前需统一的问题

### 1. 标题栏设备选择箭头间距

主界面 `LEZWR` 的文字节点 `IykqQ` 位于 x=16、宽 180，箭头 `B5pn81` 位于 x=244，文字与箭头之间约有 48 单位空隙。移除 Logo 后，应将箭头与设备名称作为一组排布，并处理长设备名称截断，避免沿用旧绝对位置。

### 2. 交互标注残留

- 个性化入口 `lIAl0` 的元数据仍是 `open-hotkey-settings`，应改为对应个性化窗口。
- 快捷键部分元数据仍记录旧的 Fn 组合，画面显示的默认值已是 R-Ctrl + F1 / F2 / F3；应统一，并复用现有左右修饰键识别逻辑。
- 更新入口仍有待提供仓库的旧标注，应根据已创建的双仓库更新说明；SC-21 的线上更新实际验证安排在正式 UI 完成之后。

### 3. 现有功能入口覆盖不足

对照 `projects/cpp/native/src/main.cpp` 的 `build_controls`，目前原型未看到以下完整入口：

- Safe Listening 开关。复查确认“关注语音”已存在于主界面通透模式中，保留原入口。
- 语音助手设置。
- 高级触摸动作配置及关联配置备份恢复。
- 诊断日志容量与保留数量设置、`.scdiag` 导出及离线回放。

建议在更多功能中补充“高级设置”和“诊断与维护”入口，承接现有功能。正式 UI 替换必须保留现有控制项、确认流程、错误反馈及更新通道选择。诊断回放仅代表离线时间线回放，不等同于硬件控制验证。

### 4. 需由实现验证的交互细节

- 自定义标题栏拖动位置、固定尺寸限制、系统菜单和关闭到托盘；禁止双击标题栏最大化及系统菜单的最大化、调整大小命令。
- 键盘焦点可见、Tab 顺序、Esc 关闭及快捷键捕获冲突反馈。
- 子窗口锚定、屏幕工作区避让、多显示器与 DPI 切换。
- 长文本、未知电量、不支持功能、蓝牙写入等待及失败回滚。

布局检查中的隐藏 DSEE、隐藏充电盒电量等节点不计为可见裁切缺陷；200% 更多页内容的裁切对应设计中的滚动视口。
