# 动态布局与窗口过渡（2026-10-15，r4）

分支：`FLEETING/ui-main-window`。分析用户录屏`2026-10-15 22-31-27.mp4`（1920×1080、60fps、17.4秒），继续修复主窗口。保留已有工作与旧程序，不修改Sony协议、会话、桌面服务或Pen。

## 录屏与代码发现

约6.6秒连接成功后，完整主页面在小窗口尚未展开时已经出现，横向和纵向内容被临时裁切；通透模式切换时也能看到窗口底边的多层条带。

原呈现顺序为：修改真实窗口尺寸/圆角区域，移动输入控件，绘制并复制新画面。高度动画还先提交一帧，再推进分段/滑条动画、触发重画。代码允许窗口几何、内容和动效不在同一次提交中更新。录屏不足以独立确认每个条带的合成来源，本轮消除这些分离提交的路径，再由新版复测实际桌面与录屏观感。

## 修改前后

| Before | After | 原因 |
| --- | --- | --- |
| 每帧先改变窗口，再补像素和圆角区域 | 先绘制完整预乘透明画面，通过`UpdateLayeredWindow`一起提交位置、大小和内容 | 避免新尺寸承载上一帧像素的中间状态 |
| 每帧重设窗口圆角区域 | 使用画面自身透明圆角；内容更新不重复提交不变的位置与大小 | 降低窗口通知与命中区域重算，保留长按/捕获行为 |
| 高度先推进，分段等随后触发第二次呈现 | 同一动画时钟先推进各动效，再统一布局与呈现 | 保持空间变化与控件动画同步 |
| 通透额外高度写死102，后续区域依赖统一偏移 | 用带稳定键的内容模块计算实际占用；后续区域依次布局 | 增删控件后高度、后续位置、裁切和命中范围一起变化 |
| 未连接与主页面立即替换 | 旧页面正文短暂淡出、新页面正文在展开后段淡入，标题栏保留 | 避免在小窗口内直接展示完整新页面 |
| 每次绘制重新生成文字布局和标题测量 | 缓存最多512条文字布局和32个标题测量结果 | 减少动效期间重复测量和分配 |

保留原Win32/Direct2D/DirectWrite、原生输入控件、键盘/UIA、拖动、滚轮和串行设备接口。透明窗口仅改变主窗口呈现方式；普通程序没有增加置顶行为。

## 模块化与型号差异

`ui_layout.hpp`中的`ModuleFlow`接收模块键和测量高度。新增模块从零高度展开；移除模块保留位置直至收起；中断时从当前已显示的高度继续；相同模块配置不会重启动画。模块可采用不同高度，后续页面可指定自己的起始坐标。

当前已有模块为环境音等级（60 DIP）和关注语音（42 DIP），两者齐全时仍保持Pen的822 DIP主窗口。不支持关注语音时收起该行，内容高度变为780 DIP。Bluetooth、设备、媒体、底栏位置均由前面的区域累计，不再按设备型号选择720/822两套窗口高度。工作区不足时继续裁切/滚动。

Sony的[WH-1000XM6官方指南](https://helpguide.sony.net/mdr/2984/v1/en/contents/TP1001872735.html)确认自动环境音开关及灵敏度设置。项目接入其真实能力和控件后，可向布局流注册相应模块和高度。当前没有添加XM6协议、假开关或虚构灵敏度值。额外42 DIP模块的插入/移除仅在纯布局测试中模拟，不代表XM6功能已实现。

## Debug断言修复

用户截图中的`operator->() called on empty optional`发生于`--ui-self-test`：鼠标路由依赖真实窗口命中，窗口被遮挡时预期滑条请求没有生成，自检仍直接访问`pending_slider->due`。

修复三处自检访问：缺少请求时记录失败，不再解引用空值。原有请求数量/数值检查全部保留。测试程序的临时窗口在运行期间置顶，确保指针场景确实命中被测控件；普通程序不置顶。纯内容更新省略不变的窗口几何提交，也恢复了长按锁定回归。
