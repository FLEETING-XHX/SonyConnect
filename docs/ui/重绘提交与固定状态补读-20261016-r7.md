# 重绘提交与固定状态补读（2026-10-16，r7）

分支：`FLEETING/ui-main-window`。本轮修复声音模式画面停留、滑块先跳到旧状态，以及音源行切换/长按固定不可用的问题。声音模式最小间隔保持 **200ms**，仍需等待上一次设备操作完成。

阶段更新（2026-10-16）：用户简单测试后反馈主界面已基本完善，并要求先提交代码，再继续更多设置页面。本次汇总主窗口及历轮相关修复为本地 UI 分支提交。此反馈不等于所有设备型号、异常场景和后续设置页完成验收。

## 证据与原因

- 读取正在运行的 r6 时，辅助功能树中的模式、音源和控件可用状态，与窗口截图存在差异。这只能说明状态与画面可能脱节，不能单凭截图判定 Sony 指令未执行。
- 新增真实屏幕回归：同尺寸下将音量从 40 改到 87，并验证原生绘制区域，使提交不能依赖 `WM_PAINT`。原生/辅助功能值与离屏画布已经是 87%，实际屏幕仍为 40%。失败日志保存在 `artifacts/ui-main-window/state-flow-r7/before-complete-frame-tests.log`。
- `UpdateLayeredWindow` 原路径在位置/尺寸未变时传入空几何参数。本机回归中，该路径保留旧屏幕内容；统一提交完整位置、尺寸与画布后，真实屏幕检查通过。微软文档允许尺寸/位置不变时使用空参数，本记录不将该可选用法描述为普遍错误。参考：[UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)。
- 外部音源变化时，会话将固定播放状态标为未知，安全检查正确地禁用了固定及音源切换；但原先没有后续补读，因此可能长期保持禁用。不能通过直接放开写入检查修复。

## 修改

### 界面帧提交和动效

- `main_window.cpp`：模型和交互变化合并为专用帧消息，不依赖原生更新区域；动画需要时直接提交完整帧。绘制过程发生的新变化安排下一帧。
- 每次提交完整窗口位置、尺寸和画布，包括尺寸不变的声音模式切换、音量、音源状态和长按围合。
- 动画计时器在布局、呈现及同步回调之后重新检查活动状态，避免回调启动的新动效被旧判断停止。
- 保留 r6 的鼠标捕获所有权修复、默认按钮松开顺序、200ms 冷却、无弹性平滑移动，以及音量 32 根/环境音 20 根 Wake 外观。

### 用户已批准的会话补读

用户明确允许补读修复并要求回归测试。本轮新增 `DeviceController::poll_playback_fixed()`，仅复用已存在的 `InteractionParameters::fix_read()`，未修改协议编码。

- 仅在连接就绪、设备报告固定播放能力、多点连接已开启、音源明确且固定状态未知时补读；已知状态不重复请求。
- 使用现有串行操作锁，不插入写指令、不设置全局忙碌、不覆盖前台操作结果。
- 用连接标识与音源变化代数检查结果。音源 A→B→A 也视为不同代数，过期读取不能恢复写入资格。
- `main_presentation.cpp` 的 `MainFixationReadback` 负责有界调度；每个连接/音源上下文最多两次尝试，重试相隔至少 1500ms，不持续刷请求。
- `main.cpp` 在现有后台队列中执行，并在入队和执行时检查上下文；无关音压/本机音频更新沿用现有队列。
- 读取失败仍保持未知/禁用；超时继续遵守原会话失效及重连规则，不绕过必要检查。
