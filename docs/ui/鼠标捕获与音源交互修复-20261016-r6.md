# 鼠标捕获与音源交互修复（2026-10-16，r6）

分支：`FLEETING/ui-main-window`。修复用户反馈的声音模式点击无反应，以及“同时连接到 2 台设备”中音源切换和长按固定失效。最小切换间隔仍为 **200ms**。

## 已复现的问题

| Before | After | 原因 |
| --- | --- | --- |
| 任意控件失焦都会全局取消交互，并释放当前子窗口的鼠标捕获 | 控件失焦只取消该控件自己的交互与捕获 | 原生按钮可能先取得捕获，再触发旧控件失焦；旧通知不能撤销新按钮的点击 |
| 旧音源行的捕获变化通知会全局取消长按/拖动 | 按通知所属控件取消，不清除其他控件的新手势 | 避免旧音源通知取消新控件的输入或另一行的长按 |
| 音源行在默认 BUTTON 处理鼠标松开之前释放捕获 | 先让默认按钮完成松开及点击通知，再清理该行交互 | 提前释放会导致系统不发送 `BN_CLICKED`，设备行看起来可用却无法切换 |
| 主要用 `BM_CLICK` 和直接命令消息验证点击 | 增加捕获交接、默认按钮过程和经过 `pre_translate` 的消息路径 | 旧测试没有覆盖捕获与失焦的实际先后顺序 |

修改前的确定性回归失败记录：

- `artifacts/ui-main-window/mode-input-r6/before-fix-tests.log`：新按钮取得捕获后，旧按钮失焦错误释放新捕获。
- `artifacts/ui-main-window/mode-input-r6/source-click-failure-before-release-order-fix.log`：仅修复失焦范围后，音源行提前释放捕获的问题仍使单击切换失败。

两个问题均在不创建耳机控制器的离线窗口中复现，不需要推测 Sony 指令。修复仅涉及 `main_window.cpp` 的界面事件处理；没有修改通信协议、会话或设备读回逻辑。

## 取消规则

`cancel_interaction(owner)` 仅取消 owner 自己的长按、开关拖动和滑条拖动；只有捕获仍属于 owner 时才释放捕获。控件失焦、子窗口取消、音源捕获变化等局部通知使用此入口。

窗口隐藏、应用失活、连接变化、显式取消及窗口销毁等情况继续使用全局取消入口。长按不足 1 秒、离开行、Escape、连接变化仍取消；长按完成只提交一次；正常松开仍可完成音源点击。

## 验证与边界

Debug 和独立 Release 编译成功，均通过 **6/6 组 CTest**；原功能窗口 **91 项**、主窗口 **27 组**离线场景通过。

新增验证包括：

- 新按钮先捕获再获得焦点时，旧按钮失焦不释放新捕获；旧音源的捕获变化不取消新按钮。
- 第二个音源行在焦点转移后，单次鼠标按下/松开只提交一次正确的协议索引。
- 无关音源的旧捕获通知不取消当前行的 1 秒长按。
- 关闭→降噪、降噪→关闭以及另外四个方向全部覆盖；分别检查原生按钮过程和经过消息循环的点击。派发时同步更新 busy，模拟正式适配器的重入更新。
- 继续检查 200ms 冷却、慢回读、失败回滚、长按围合、退出/移出取消、音源状态、真实屏幕音量像素、高 DPI、动态布局和资源稳定性。

上述鼠标路径使用真实 HWND 的离线消息夹具，不代表蓝牙硬件验收。没有向用户当前运行的耳机程序发送模式或音源切换指令，没有退出或覆盖正在运行的 r5。新版仍需用户实机确认切换和固定播放结果。
