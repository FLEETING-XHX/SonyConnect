# 主窗口稳定性与 Wake 样式（2026-10-15，r5）

分支：`FLEETING/ui-main-window`。本轮只修改主窗口呈现、UI 输入门控及相关测试；保留现有未提交工作、旧版程序和用户提供的 React 源文件，不改 Sony 协议、会话或桌面服务。

## 修改前后

| Before | After | 原因 |
| --- | --- | --- |
| Wake 圆角由半宽圆角纵向压缩得到，环境音条偏高 | 小圆角矩形，半径为短边的 18%，最大 2 DIP；环境音条高 12 DIP，音量条高 14 DIP | 按用户新截图保留直边和小圆角，改善横条/竖条比例 |
| 透明画布和淡入图层强制使用 ClearType | 统一使用灰度文字抗锯齿，字体与文字颜色定义保持原值 | 避免透明目标上的亚像素颜色/覆盖率异常 |
| 模式点击后动画首帧才更新原生按钮可用状态 | 点击即锁定原生按钮，并在分发前检查临时目标、busy、冷却及重复选项 | 防止排队点击在首帧前再次分发 |
| 无主窗口声音模式冷却 | 两次接受切换至少间隔 **200ms**；如果操作尚未完成，继续等待现有回读结果 | 用户最终指定 200ms；计时器不阻塞 UI，也不提前解除真实 busy |
| `WM_DRAWITEM` 通知再次使整窗失效 | 只确认通知，由实际状态变化请求绘制 | 切断原生通知触发整窗绘制的反馈路径 |
| 每次父窗口 `WM_PAINT` 都提交整帧 | 增加画面脏标记及绘制重入保护，布局忙标记由作用域自动复位 | 合并无效重绘，避免同步通知嵌套 Direct2D 绘制；托盘恢复主动请求一帧 |

音量继续为 **32 根**，通透环境音为 **20 根**。Wake 不增加波浪或弹性，Elastic 切换、滚轮、实时数值、键盘/UIA、原有失败提示和状态回滚保留。

## 事实与未确认部分

- 微软文档说明：透明渲染目标通常应使用灰度抗锯齿；强制 ClearType 可能导致不可预测的结果。原实现确实存在这个组合；目前离线重复操作和托盘恢复的深色标题像素保持一致，但没有在测试机重现用户那一次白字现场。
- 代码中确实存在绘制通知反向触发父窗口绘制的路径，也缺少首帧前的模式输入门控。本轮已修复这些路径。没有取得用户卡住时的线程栈，不能断言所有卡住都来自同一原因。
- 冷却仅限制主窗口声音模式分段的接受频率，不代替原串行工作队列、设备 busy 或读回确认。失败仍恢复设备已确认状态，不通过清除 busy 或吞异常来解锁。
- 600ms 是本轮最初方案，已按用户最新要求改为 200ms，最终构建和验证以 200ms 为准。

## 验证

Debug 与独立 Release 编译成功，均通过现有全部 **6/6 组 CTest**。旧功能窗口 **91 项**、主窗口 **24 组**离线场景通过；协议/会话/桌面模拟测试保留。

新增检查：

- 12 轮接受切换，每轮注入 100 条重复点击通知：每轮只分发一次请求，按钮立即锁定，快速回读也不能绕过 200ms。
- 慢回读超过冷却仍不可切换；再次点击已确认的当前模式不发送冗余请求。
- 连续模式变化后的标题深色像素保持一致；隐藏/恢复后继续一致。
- 向父窗口发送 500 条原生绘制通知，空闲 200ms 新增绘制不超过 1 次；GDI 与 USER 对象数不随这组连续操作持续增加。
- 检查透明画布内部 alpha 为 255；真实屏幕音量数字、离屏打印与 PNG 一致性均保留，实际屏幕的两个数字都必须可见。
- 原有失败回滚、底部锚定动画、长按围合、滚轮、动态模块及高 DPI 标题栏裁切检查继续通过。

首次测试受桌面遮挡影响：同环境下未修改的 r4 对照程序也在滚轮命中处失败。测试夹具改为实际激活其临时窗口，并在屏幕采样前检查暴露状态；不再允许被遮挡时跳过真实屏幕像素断言。此变化只作用于测试程序，正式主窗口不置顶。

本轮没有进行真实蓝牙连续切换或多小时运行验收；离线点击计数和像素检查不代表所有硬件环境下的挂起已经排除。
