# 主窗口视觉与音压修复（2026-10-15，r3）

分支：`FLEETING/ui-main-window`。延续已有未提交工作；本轮不修改 Pen、用户 React 源文件、蓝牙协议或会话实现。

## 录屏分析

参考：`C:/Users/FLEETING/Videos/2026-10-15 22-14-33.mp4`，1920×1080、60fps、约12.22秒。

约1.1秒开始切换时，关机图标、第二台设备的名称和状态短暂变浅，同时右上“已确认”变化为操作提示。代码中这些控件因临时输入锁而使用禁用颜色，可以解释这部分可见闪烁。现在保留输入锁，按真实能力/连接状态绘制颜色。

录屏缩放过程中也能看到底边短暂多层条带；单凭录屏不能区分窗口合成与捕获表面的影响。本轮沿用单画布绘制，没有根据这个现象重写窗口架构。修复后的最终桌面观感仍需用户复测。

## 修改前后

| Before | After | 原因 |
| --- | --- | --- |
| Wake 直接绘制等半径胶囊，宽条接近椭圆 | 按圆角矩形先成形、再纵向压缩的顺序计算独立横纵半径 | 对齐提供的 React/CSS 形状，保留直立边缘 |
| 音量条较短、环境音宽而扁 | 音量32根、环境音20根，间隔4 DIP；静止高度分别16/20 DIP | 按最新明确要求保留各自 Bars 数量，改善参考图中的比例 |
| 操作中关机、非活动设备和未选声音模式会变灰 | 可用能力和已连接行保持原色，仍禁止冲突操作 | 分离视觉状态与临时输入锁 |
| 每次更新显示切换、确认、已确认文字 | 正常操作不显示回读标签，仅失败显示“回读错误，请重试” | 去掉反复变化的成功提示 |
| 失败显示普通红字 | Pen 20/21 的219×26、圆角6提示条，图标/文字`#B56C25`、背景`#FFF2E4` | 复用原型反馈样式；不新增可点击重试控件 |
| 播放区只有独立音符，播放按钮偏小 | 42×42浅色图标底板、20 DIP音符、36 DIP播放按钮、调整文本及按钮间距 | 读取当前 Pen 的媒体区尺寸与布局 |
| 歌名下显示`cloudmusic.exe`等应用名 | 显示“来自”加耳机确认的当前音源名称；切换音源后随之更新 | 播放来源对应设备；未知时显示“音源待回读” |
| 音压轮询仅检查“更多”第一页可见 | 主窗口或“更多”第一页可见且未最小化时均可轮询 | 修复只打开主窗口不能主动取得音压的问题 |

请求失败仍清除临时选中目标，回到设备快照中的确认值；不会追加一条盲目的反向设备写入。若连接已断开或设备值未知，仍显示未知/断开，不伪造已恢复的硬件状态。

音压继续使用已有`poll_sound_pressure()`接口与串行后台队列；前台操作期间让出队列。设备现有的最小更新间隔、功能开启/能力限制保持有效；隐藏/最小化所有相关窗口后不主动轮询音压。
