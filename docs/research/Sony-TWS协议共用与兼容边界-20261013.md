# Sony TWS 协议共用与兼容边界

2026-10-13。核对本地固定 checkout，并查阅上游支持页面；没有更新参考仓库、修改产品代码或操作耳机。

## 结论

许多现代 Sony TWS 共用 MDR V2 封包、握手、能力查询及功能参数体系，适合复用一套协议引擎。WF-1000XM5 验证能证明其中已覆盖路径在该型号／固件上的表现，不能证明多数 Sony TWS 已实测兼容，也不能直接放行所有型号写入。

应按协议族、功能能力 ID、参数布局、合法范围和固件差异适配；按型号／固件记录实机验证。型号只作候选识别和已验证限制，不代替设备能力。

## 共用与差异

- **基础协议可复用**：Gadgetbridge 的 SonyHeadphonesProtocol.java 将 WF-1000XM4、WF-1000XM5、LinkBuds、LinkBuds S 的记录握手交给同一个 SonyProtocolImplV2；WF-SP800N 的记录握手则进入 V1。不能用“都是 Sony TWS”或型号数字决定协议代际，尤其 WF-XM4 与 WH-XM4 不能混为一谈。
- **功能不齐全**：官方兼容表本身按型号区分降噪、智能免摘、DSEE、触摸、音压等。WF-C700N 的上游记录支持环境控制、EQ 和多点，但不支持提示音量调整、智能免摘和摘下暂停；不能套用 XM5 全部控件。
- **相同功能仍有不同布局**：电量单耳／双耳／盒、阈值；环境控制参数和动作循环；EQ 段数／步数／BASS；提示开关是否携带语言、是否允许音量；多点与音源列表均需解析实际能力。当前 WF-1000XM5 的循环已实际证实存在于 F3 / 35 预设可定制动作，未报告独立 69 路径。
- **固件可以改变实际效果**：固定 SonyHeadphonesClient 的 WF-C700N.md 记录 2.0.5 对环境控制写入 ACK／通知均像成功，但实际声音模式不变；2.0.7 修复，发送帧保持相同。此为上游记录，不是本项目实测。即使帧和回读符合预期，仍需检查实际行为。
- **旧协议不能沿用新协议保证**：当前 SonyConnect 握手明确拒绝 V1；尚不能把 V2 验证推广到 V1 耳机。

## 当前 SonyConnect 的实际边界

ProtocolDeviceBackend 的型号状态主要识别 WF-1000XM5／WH-1000XM5；电量查询还依赖该型号的布局。声音、EQ、双设备、触摸和扩展设置的多个写入门禁明确限制 WF-1000XM5。因此目前产品不是所有 V2 TWS 自动兼容，即使底层框架具备复用基础。

WF 右耳分配失败仍未定位，不能把这一功能作为已完全验证的通用基线。这个问题与是否使用快速切换分别核对。

## 后续建议

1. 先修当前 WF 右耳问题，保存已确认的功能布局与回归样本。
2. 增加按协议／能力布局选择的设备配置，未知型号先只读；不直接取消当前写入保护。
3. 条件允许时优先交叉核对 XM4 或 LinkBuds S，再用 C700N 等不同功能组合检查回退；借用设备即可，无需为了兼容声明购买全部型号。
4. 每个新型号至少取得握手／功能表、固件、当前参数及代表性实际写入＋恢复证据。重复布局可复用回归；新增布局、功能及固件问题单列。
5. 发布表区分“本项目实测通过”“上游证据／实验性”“未知或不支持”，不使用未经统计的兼容百分比。
