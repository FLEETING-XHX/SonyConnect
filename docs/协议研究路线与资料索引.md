## 路线建议

以已有开源协议定义、实现与测试为起点，官方 APK 用于缺项和冲突的专项核对，最终以目标耳机的命令响应、回读及实际行为验收。技术路线建议继续采用 C# / .NET 10 / WPF，协议知识来源不要求与程序实现语言相同。

这不是对三个仓库机械投票。部分项目共享上游；相同命令出现于多个派生项目不构成多次独立验证。每项功能需记录最初来源、分支 / commit、型号、固件及验证方法。

APK 是官方实现的分析材料，能帮助确定命令字段和应用调用流程；它不是可直接在 Windows 使用的公开 SDK。静态代码里有某字段也不等于 WF-1000XM5 当前固件会启用它。先分析全部 APK 再开始功能开发，会扩大逆向范围和维护负担；建议按具体缺项追踪。

## 固定播放：已找到对应 WF 实机依据

[PR #57：Fix playback device on multipoint](https://github.com/mos9527/SonyHeadphonesClient/pull/57) 已合并。作者报告在 WF-1000XM5、固件 6.1.0 上验证官方 App 与该客户端的固定 / 解除状态。

- SOURCE_SWITCH_CONTROL 的字段是“允许自动切换”：1 表示允许，0 表示固定。UI 中“已固定”的布尔值不能直接照写这个字节。
- 固定针对当前播放设备；固定另一设备需要先确认活动音源，再提交固定。
- 通话或语音助手占用时可能拒绝固定，需要读取失败原因。
- PR 包含未固定和通话拒绝样本，没有成功固定状态的抓包样本；成功行为是作者实机报告，仍须在用户耳机验证。
- 当前本地 C 接口已有 Get / SetSourceSwitchControl 与结果读取接口；上层 C#、长按 UI 和失败反馈尚未实现。

上述资料使固定播放具备明确实现线索，但不把“已找到命令”标为“SonyConnect 已实现”。长按取消、等待耳机确认、右键解除和拒绝后回退仍遵循交互说明。

## 建议执行顺序

1. 建立功能与来源矩阵；优先核对 WF-1000XM5 的连接、电量、声音模式、EQ 和关机。
2. 参考 sony-tray 建立可诊断的 C# 连接与协议基础；核对 mos9527 的版本与能力，逐项移植需要的功能。
3. 在用户 WF 上验证，保存时序与发送 / 接收记录，形成离线回归测试。
4. 高级功能按同一路径扩展，优先固定播放、双设备列表、提示音量与触摸模式循环。
5. 仅对未覆盖、字段含义冲突、当前固件行为不同的功能分析 APK，再用官方 App 单项操作的抓包对照。
6. APK 更新或耳机固件更新后，根据功能回归结果确定是否需要重新研究，而不是每次整体逆向。
