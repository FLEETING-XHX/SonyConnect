# SC 阶段模型与推理强度建议

核对日期：2026-10-12。适用于 SonyConnect 的 C# / WPF 项目。

## 建议先采用的配置

把 `gpt-6-luna / medium` 用于范围明确、可复用现有接口的界面和本机功能；把 `gpt-6.1-sol / medium` 用于新增协议能力、Windows 系统集成和跨模块状态协调。遇到并发、重连、取消、资源释放或难以复现的故障，再使用 `gpt-6.1-sol / high`。

不要所有 SC 都使用高推理强度，也不要只为省额度把所有任务交给较小模型。判断标准是完成一个可靠任务的总消耗，包括返工、验证和排错，而非单次回答消耗。

以下是本项目的工程判断，不是模型能力保证或实际额度测量结果。“智能体”在这里指执行任务的模型；每项默认由一个智能体完成，不默认启用多个并行智能体。本文件仅给出选择建议，不自动改变客户端模型或推理设置。

## 模型与推理档位依据

官方将 GPT-6 Luna 定位于聚焦、高频且注重成本的任务，将 GPT-6.1 Sol 定位于智能与成本的平衡选择，将 GPT-6 Astra 用于最复杂的工作。这支持分层选择，但不能证明较小模型适合所有项目任务。[官方模型选择说明](https://developers.openai.com/api/docs/models)

官方说明：较低推理强度通常减少推理 token 和延迟；涉及诊断、规划、代码和多步权衡时可选择 medium/high。xhigh/max 应有代表性任务的质量收益证据，再判断额外成本是否值得。[部署与推理强度说明](https://developers.openai.com/api/docs/guides/deployment-checklist)

Codex 额度同时受模型、任务复杂度、上下文、推理、工具调用、检索及缓存影响。API 单价不能直接换算成当前账户的订阅额度倍率，因此本文件不承诺节省百分比或固定消息次数。[官方额度说明](https://learn.chatgpt.com/docs/pricing)

| 选择 | 本项目用途 | 默认强度 |
| --- | --- | --- |
| gpt-6-luna | 已有接口上的 WPF 布局、绑定、常规设置、文档整理和确定性小修改 | medium；纯文字或机械性小修改可 low |
| gpt-6.1-sol | 协议适配、Windows API、状态一致性、测试设计和复杂功能集成 | medium；有明确复杂性再 high |
| gpt-6-astra | Sol 已有可复现反例且仍无法解决的复杂问题，集中分析最困难部分 | high，按需要临时使用 |

当前客户端也提供旧版 Sol / Terra / Luna，但不能仅凭“旧版”就认定更省额度或更适合本项目。先用上面两档主力建立可比较的完成质量与消耗记录即可。下面只使用当前客户端明确支持的 low / medium / high 档位；API 支持的其他档位不意味着当前客户端一定可选。

## 升档与节省额度的执行方式

1. 每次限定一个 SC 或一个可独立验证的子任务，先读对应 Issue、阶段文档和直接相关代码。不要每次扫描全部上游仓库、APK 和历史日志。
2. Luna 遇到未知协议、系统 API 语义、跨模块状态冲突时，先保存复现、相关源码位置和失败日志，再用 Sol 分析。重复同一修改却没有新证据，不应继续低档盲试。
3. Sol / medium 对确定的局部实现通常足够；并发、取消、恢复或多个相互矛盾的证据才升 high。xhigh/max 不作为日常默认值。
4. 模型升级不能补出不存在的协议资料、耳机或运行环境。资料不足先补来源；硬件不足明确待实测；底层修改仍按 AGENTS.md 先说明方案并获得确认。
5. 默认一个执行智能体；若以后授权并行，限定互不冲突的任务和文件，不让多个智能体各自完整扫描、实现同一个 SC。
6. 使用精确搜索、限制日志输出、复用已有构建/回放脚本。先跑与改动相关的检查，再完成阶段规定的编译和回归；没有新改动或新失败时，不重复整套测试。
7. UI 调整用必要的截图核对布局和交互；截图、模拟数据不能代替真实控制成功证据。不要通过少测、关异常或删功能来降低消耗。
8. 记录任务范围、选择的模型/强度、返工情况、验证结果及可取得的额度变化，再调整选择。并行任务和共享账户消耗会干扰额度归因，不把一次窗口差值当作固定倍率。

## 下一阶段的具体选择

SC-7 建议先用 `gpt-6-luna / medium`，复用 SC-6 的简易验证窗口、自动日志和回放能力，补齐 Issue 要求及诊断导出。先核对已有实现，避免重复搭建；遇到跨会话回放、脱敏或状态隔离问题再切 `gpt-6.1-sol / medium`。

SC-8 起涉及尚未实现的耳机能力，优先用 `gpt-6.1-sol / medium` 做协议核对和实现，确认接口后可用 Luna 做 UI。正式 UI 的 SC-23～SC-25 再以 Luna 为主。
