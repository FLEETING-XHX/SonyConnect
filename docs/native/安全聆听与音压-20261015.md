# 安全聆听开关与当前音压

2026-10-15，C++ 原生工程。在“连接与声音”页增加“启用安全聆听”和当前音压显示。

## 使用与状态

- 点击开关立即提交，收到耳机模式通知后才确认勾选状态；ACK 本身不代表开关成功。
- 首次连接若尚未收到模式通知，开关显示未确认状态。点击即可请求启用，不把未知状态冒充关闭。
- 开启成功后显示耳机提供的整数 dB；未播放、通话中、未佩戴、读取失败和过期读数分别显示状态，不使用 0 或 255 代替有效测量。
- 关闭后立即清除音压显示并停止查询；再次开启会重新读取。
- 本机按设备保存已确认的启用偏好到 `%LOCALAPPDATA%/SonyConnect/Native/safe-listening.ini`，更新前保留 `.bak`。重连后会重新确认已启用的偏好；不会因为配置里写着开启就直接显示为已确认。
- 听音历史、累计剂量、健康阈值提醒和自动限制音量不属于本次功能。当前数值不宣称具有声级计校准精度，也未确认是否为 dBA。

## 协议与实现

- 在设备实际上报的 V2 Table2 支持 ID `50/51/52/53` 中选择唯一明确的布局，对应 type `00/01/02/03`。不按机型写死；多个不同布局同时上报时保守禁用。
- `50/51` 获取能力及最小轮询间隔；`56/57` 获取可用性，57 不含模式开关。
- `58 type onOff 01` 设置正常模式、关闭预览，`00=ON`、`01=OFF`；`59` 通知确认正常模式和预览两个字段。超时或不匹配不会显示虚假的成功。
- `5A type` 查询，`5B type level cause` 返回当前值。`cause=00/01/02` 分别为未播放/通话/未佩戴；其他状态按官方 App 的 OUT_OF_RANGE 映射分支，且仅当 `level != FF` 时显示数值。不能仅接受原始 cause=FF，否则会漏掉实机的数值分支。
- 查询使用已有封包、ACK、序号、收包与连接隔离机制。参考项目和 APK 均不参与产品构建，没有复制反编译代码。
- 音压查询遵守耳机返回的秒级 minimumInterval，零或未知间隔不轮询。后台查询不设置全局 busy、不覆盖用户操作结果。
- 只在主页可见且窗口未最小化时轮询；更新静态文本，保留其他控件、焦点和下拉框。媒体/蓝牙状态检查仍维持独立节奏。
- 离线/断开后禁用写入并隐藏旧读数。重连先读能力，恢复偏好也必须收到新的耳机确认。

涉及文件：`protocol.hpp/.cpp` 增加类型、格式校验与请求；`session.hpp/.cpp` 增加状态、通知确认与限频读取；`main.cpp` 增加开关、显示、偏好和界面回归检查；两个现有测试套件增加协议/会话场景。

## 验证边界

本次用户授权直接使用当前播放音乐的蓝牙耳机测试。实机为 **WF-1000XM5，固件 6.1.0**。

已经实际观察：开启得到模式确认；音压显示 51、53、57 dB 等变化读数；关闭后显示“安全聆听已关闭”；再次开启恢复读数。命令日志中可见 Table2 `58→59` 及 `5A→5B`。关闭期间未继续查询。此为耳机遥测通路/界面验证，不是外部仪器校准结果。

实机展开耳机下拉框后，音压从 37 dB 更新到 50 dB，列表仍然保持展开。测试期间还出现一次 `5A` 请求未收到 ACK/回复，约 5 秒后由已有会话隔离与重连机制恢复；恢复后重新确认安全聆听并继续显示音压。尚未确认这次无响应的根因，不据此宣称长时间运行完全无掉线。

Release 编译通过，CTest 四组全部通过：59 个协议场景、56 个会话场景、桌面测试及 78 个 UI 场景；便携包额外通过离线 UI 检查。构造测试报告继续保留 `HardwareVerified=false`，与本段实机功能验证分开。

本地命令时间线保存在 `artifacts/native/sound-pressure-20261015/device-command-timeline.json`，只保留相关命令及时间，不包含蓝牙地址、原始控制负载或其他应用内容。离线构造值与实机观察分别记录。

尚未实测：WH 系列、新固件/其他机型、手机音源与电脑音源的官方 App 同步对照、通话/摘下状态、计量精度及频率加权。特殊状态、ACK 未确认、拒绝、零间隔、限频、断线隐藏与弹出框稳定性由离线回归覆盖，不标为硬件通过。
