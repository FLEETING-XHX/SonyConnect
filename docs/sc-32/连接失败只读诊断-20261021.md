# WH-CH720N 控制连接失败：只读诊断

日期：2026-10-21。目标：WH-CH720N，固件 1.0.8。当前仅诊断，未修改产品协议、会话、超时策略或耳机设置；SC-34 工作区改动保留。涉及真实控制链路，按 L3 对待。诊断辅助程序集中在 `artifacts/sc-32/diagnosis/`，未加入产品构建。

## 已确认的事实

1. 本机最近两份正式应用日志（02:10 UTC 与 02:30 UTC）在连接失败前均已建立 RFCOMM，并完成六阶段初始化：协议、能力标识、型号、固件、Table 1 与 Table 2 支持列表。
2. 最新两次重连均在发送 Table 1 的命令 0xE0 后收到 ACK，随后约 5 秒没有对应数据响应。程序报告 query-timeout，再主动隔离并关闭控制通道。随后的 RFCOMM receive 10038 出现在主动关闭之后，不是此次失败的首个事件。
3. 只读硬件探针使用现有 `discover_paired_devices`、`ProtocolSession`、`Handshake`：只选择当前已连接且名称含 WH-CH720N 的设备。实测六阶段握手完成，返回型号 WH-CH720N / 固件 1.0.8。
4. 实机 Table 1 报告连接模式功能 0xE1，现有实现为它规划 E0 00、E2 00、E6 00 三条查询。ConnectionPreference 在 feature 排序中先于 DSEE，因此应用握手后的首个 0xE0 对应 E0 00。
5. 额外只读实测使用现有 E6 00 读取当前连接质量参数，成功返回 E7 00 00。未发送 E8 设置命令、未改变降噪/EQ/DSEE/音源/连接质量等耳机设置，也未重新发送已知会超时的 E0 00。

## 定位

当前 `ExtendedParameters::read_queries` 对普通扩展功能统一安排 capability → availability → parameter，包含功能 0xE1 的连接模式。在这台耳机上，前置 E0 00 得到 ACK，但没有能力响应，从而阻断后续本可成功的 E6 00，导致整个初始化失败。问题定位在功能查询规划的型号/能力差异处理，而不是 Windows 没有配对，也不是本机控制服务完全连不上。

独立对照的本地固定版本 SonyHeadphonesClient（MIT）中：

- `libmdr/src/HeadphonesV2.cpp` 的 Connection Quality 分支，对 `CONNECTION_MODE_SOUND_QUALITY_CONNECTION_QUALITY` 只调用 `AudioGetParam(CONNECTION_MODE)`。
- `libmdr/src/HeadphonesV2T1.cpp` 的能力响应分发仅处理 UPSCALING，没有 CONNECTION_MODE 能力分支；参数分发明确处理 CONNECTION_MODE。

“不发送 E0 00”的判断来自参考调用、响应分发和本机 ACK/超时与 E6 回读三组证据。不能从这一结果推断所有其他扩展功能也没有能力/状态查询，更不能统一忽略超时来伪造连接成功。

## 证据

- 原应用日志：`%LOCALAPPDATA%/SonyConnect/Native/Logs/run-20261021-023042736-5007e6ee8b4e4021bd82907c595cef5a-0.jsonl`。
- `artifacts/sc-32/diagnosis/wh-ch720n-handshake.txt`：只读六阶段握手及原规划；能力标识中的地址信息已脱敏。
- `artifacts/sc-32/diagnosis/wh-ch720n-read-preference.txt`：握手与 E6 00 → E7 00 00 的硬件只读结果。
- 辅助程序源码和编译脚本与记录同目录；使用当前 Release session/protocol 静态库构建，编译及两次有不同目的的只读硬件诊断均通过。

## 修复方案与影响（待确认）

- 在对应连接模式 profile 中明确是否存在独立 capability/status 查询。已证实的 0xE1 只安排真实参数读取，不再发送无对应证据的 E0 00/E2 00；保留 WF 使用的其他 profile 查询路径。
- 同步修正该 profile 的值域/状态初始化及读取状态更新，不能仅删查询后让有效回读继续被“无 choices”丢弃；沿用设备能力与实际回读驱动 UI，保留现有功能及设置确认机制。
- 保留 ACK 不等于响应、超时隔离、迟到响应保护；不延长超时掩盖错误，不整体跳过初始化。
- 对照检查后续初始化查询是否还存在相同假设；新增 0xE1 握手及参数状态的定向集成覆盖，保留 WF profile 回归，再在这台 WH-CH720N 上做先只读的完整连接验证。
- 修改将涉及共享协议查询规划与会话状态处理，属于 L3。依据 AGENTS.md 二.6，获得确认后才修改；当前产品 `protocol.cpp` / `session.cpp` 相对 HEAD 无差异。
