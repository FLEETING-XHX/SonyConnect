# 循环设置已经变化但提示回读未确认

2026-10-21，风险 L3。用户截图为 `Readback did not confirm the requested value; actual device state is retained.`，并反馈设置实际已改变。本轮修复延续循环控制的现有授权范围；修改前已 fetch Gitee，保留所有此前工作。

## 原因与证据边界

此前为 ANC 增加的有界状态确认只在声音设置调用中启用。`DeviceController::set(Feature::AmbientCycle)` 的独立按钮路径及 WF 自定义触摸循环路径仍使用立即比较：设置 ACK 后发起一次读取，只要合法回读仍为旧值便返回上述错误；之后的目标通知会正常更新设备状态，却不能改变已结束请求的失败结果。

错误文本由这一比较分支产生，不能据此认定是 Windows 蓝牙未连接或设置命令没有发出。用户反馈符合迟到生效/通知的表现；但现有运行日志只有命令编号，缺少循环 subtype 和目标/实际参数，因此没有将这次用户设备的每次报错时序当作已抓包确认。最终实机效果仍待复测。

## 修改

- `projects/cpp/native/src/session.cpp`：循环设置沿用已有 ANC 确认等待机制，在有界窗口内等待匹配状态，并按既有读请求规则复查。独立循环参数及 WF 自定义动作派生循环值更新时唤醒等待；原声音条件变量改名为参数变化条件变量，声音行为继续受原用例覆盖。
- 循环设置命令只发送一次。后续仅查询，不补发 setter；WF 路径仍保留完整动作列表，不改变无关动作。连接、意图、睡眠或蓝牙状态变化会取消确认。
- 首次合法但为旧值的回读不再立即结束为失败。若参数始终未匹配，仍返回未确认错误并保留实际值；如果读请求本身 ACK 后没有业务响应，继续返回超时并保留协议隔离，不能用稍后通知掩盖传输失败。
- 未改协议字节、循环组合限制、设备能力门控、UI 错误可见性或其他设置的确认策略。前一轮 DSEE、横向电量图标及 WF 文字稳定性修复包含在本轮构建中。

## 实际验证

`projects/cpp/native/tests/session_tests.cpp` 新增五项：

1. 独立按钮和 WF 自定义动作两条路径，首次读取旧值、稍后通知目标值，最终确认成功且只写一次；保留 WF 的其他固定动作。
2. 无通知时由后续只读查询确认目标，不重发设置。
3. 始终保持旧值时仍失败，实际值保留且只写一次。
4. 回读 ACK 后静默仍超时，不假报成功。
5. 等待确认期间断连，取消旧目标且只写一次。
