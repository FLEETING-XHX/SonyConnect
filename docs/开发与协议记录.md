## 关键发现

1. SonyHeadphonesClient 的 WF 支持表有多项支持声明，但未逐项给固件；WH 表注明提示音量不支持、音源切换/智能免摘未测试、媒体通知有问题、EQ 无预设选择。sony-tray 的 WF 是 best-effort，sony-device-center 的 WF 是 untested。全部不能当作 SonyConnect 本机通过。
2. Gadgetbridge WF coordinator 为 `coordinators/SonyWF1000XM5Coordinator.java`，`isExperimental()` 返回 true；注释称环境声未完全工作、耳机音量可能有问题。默认能力不是本机能力查询。
3. [PR #57](https://github.com/mos9527/SonyHeadphonesClient/pull/57) 在线与离线补丁一致：WF-1000XM5 / 固件 6.1.0 有作者固定播放实机报告，抓包仅含未固定与通话拒绝，没有成功固定抓包。线值 1 允许自动切换，0 固定；固定其他目标应先切换并确认活动音源。本机仍未验证。
4. C API 有 `mdrHeadphonesGet/SetSourceSwitchControl` 和 `mdrHeadphonesGetSourceSwitchControlResult`。后者仅在写入后收到 `MDR_EVENT_PAIRED_DEVICES_CHANGED` 时有保证。ACK 或动画结束不能代表成功。

## SC-18

## 可复现命令与 Rider

在仓库根目录，用 Windows 自带的 Windows PowerShell 5.1：

发布脚本执行锁定还原并复制固定版本许可告知，再运行 `dotnet publish -c Release -r win-x64 --self-contained true --no-restore`。关键属性记录在 csproj：`PublishSingleFile`、`IncludeNativeLibrariesForSelfExtract`、`DebugType=embedded`；关闭裁剪、ReadyToRun 与压缩。脚本校验发布目录恰好一个 EXE，不删除多余文件，也不写入机器级环境变量。

`packages.lock.json` 锁定隐式 ILLink 构建依赖；Windows SDK 引用包及运行时 pack 不全部显示在 PackageReference 锁文件中。因此发布清单另记真实 runtime/projection nupkg 版本、大小、SHA256 和所有嵌入告知的哈希。空白的显式 PackageReference 不意味着零依赖。SDK 固定后升级 SDK/运行时仍需重新发布验证和核对许可，不能继续引用旧记录。

Rider 打开 `SonyConnect.sln`，选择 SC2Probe / Debug，工具链使用 .NET CLI 的 SDK 10.0.401，可在 `Diagnostics.RunAsync` 设断点。Debug 使用本机 Windows Desktop Runtime；Release 发布 EXE 自带运行时。此 solution 的 x86/Any CPU 入口只是生成的映射，项目实际固定 x64，不能当作已经支持 x86。模拟耳机传输留给 SC-3/SC-7；本轮可运行系统 API 探针，不提供耳机模拟器。CLI 构建已验证，Rider 调试操作未验证。工具链设置参考 [JetBrains 官方说明](https://www.jetbrains.com/help/rider/Settings_Toolset_and_Build.html)。

# 状态与接口约定

## 依赖与替换位置

Core 无上层引用，Application → Core，Infrastructure → Application，Presentation → Application，App → Infrastructure / Presentation。WPF 类型留在 Presentation / App。Infrastructure 当前为纯 .NET 模拟 / 未接入实现；Windows 适配按需调整该项目目标框架，平台类型不进入 Core / Application 的接口。

`CompositionRoot` 是组合入口。发现使用 `IDeviceDiscovery`，控制使用 `IDeviceControlGateway`，后续字节连接使用 `IDeviceTransport`。按钮调用 ViewModel 异步命令，再调用 `IDeviceUseCases`；视图事件只转交选择动作。

正式 UI 通过 `ControlPanelViewFactory.Register(ControlPanelKind.Designed, factory)` 接入，`Create` 接受现有 ViewModel。当前只注册 Simple，`--view designed` 会报告正式视图尚未接入。

## 值与能力状态

| 状态 | 含义 | 值载荷 |
| --- | --- | --- |
| Unknown | 字段 / 枚举 / 类型无法确定 | 无 |
| Unsupported | 明确不适用或设备报告未支持 | 无，保留原因 |
| NotRead | 尚未读取 | 无 |
| Known | 已获得确认读数 | 值、来源和观察时间 |
| ReadFailed | 本次读取失败 | 可保留上次确认值，并含失败原因 |
| WriteFailed | 本次写入失败 / 拒绝 / 取消 | 可保留最后确认值，并含失败原因 |

不存在使用 `default(T)` 提供读数的入口。确认的 false、0%、0 dB 是有载荷的 Known，未知 / 未读取没有载荷。读取失败保留结构上未支持的电量项。

WF 电量为 Left / Right / Case，WH 为 Single；其他结构项不适用，未知型号不推断结构。电量范围 0～100，EQ 五段为 −10～+10 的整数。充电状态与电量分别记录，盒子读数带观察时间。

固件、环境声音、关注语音、EQ 开关 / 预设 / 五段 / CLEAR BASS、多点 / 音源列表 / 活动音源 / 固定音源 / 编码均有独立字段。Known 的 `PlaybackLock(null)` 表示已确认解除固定，NotRead 没有确认载荷。

能力按读取 / 写入 / 通知分别为 Unknown / Unsupported / Supported；没有报告的项保持 Unknown。能力查询本身区分 NotRead / Known / ReadFailed。运行时报告与 `HardwareValidation` 分开，后者包含型号、固件、时间和条件。模拟报告来源为 Simulation，实机验证为空；不凭型号预填功能支持。

## 会话与操作

选设备、断开或控制链路丢失时，先生成新的 SessionId 并清除固件、能力、读数和进行中操作，使旧结果失效，然后取消 / 清理旧会话。重连同一设备也拒绝旧会话响应。音频连接与控制连接独立，控制断开时音频可以仍然连接。

`DeviceUpdate` 带会话与会话内递增观察序号。通知和回读进入统一更新路径；较旧数据不能覆盖较新通知。`HeadphoneState.Revision` 也让呈现层拒绝排队的旧快照。

成功结果必须有当前会话、已连接控制链路的确认读数。模式写入还需确认值与目标一致；不一致显示写入失败并保留实际确认值。只有 ACK 时返回 PendingConfirmation，保留上次确认值。

请求中使用 PendingOperation。结果为 Succeeded / PendingConfirmation / Failed / Canceled / Superseded / Busy；并发设备用例返回 Busy，未知 / 未支持写入在调用网关前阻止。取消、超时、传输错误、拒绝、非法参数和过期会话分别保留原因。

退出取消会话并释放网关与 ViewModel 订阅，迟到结果不能填回状态。实际协议请求关联、队列合并、ACK 等待、超时计时和重试由 SC-6 接入；模拟结果不构成协议或实机支持。

## 2. 能力映射的含义

映射依据为 V2 两张表的 `FunctionType`；具体编号直接列在 `MdrCapabilityMapper.cs`。电量的单体 / 左右 / 盒映射 20/28、21/29、22/2A；环境声与 EQ 等保留经过来源定义的对应编号；Table 2 的配对设备管理 / 音源控制映射来源 30/32/33、31。

已声明映射功能：Read=Supported，Write / Notify=Unknown，表示设备声明该功能可用，后续仍需读取参数与实现用例。查询尚未完成的表：Unknown。完整已读表中没有对应编号，或协议明确关闭该表：对应已研究功能为 Unsupported。未建立映射的功能继续 Unknown，原始编号仍可查看。

型号文本、优先级或回放不能新增 `HardwareValidation`。传入 `Observation` 标明 Device / Replay / Simulation；离线测试使用 Replay。将来需要扩充映射时必须补参数能力证据及回归，不仅按名称添加可写字段。

## 3. SC-5 / SC-6 接入约定

1. 每个真实连接创建新的 `SessionId`、`TandemStreamDecoder` 和 `MdrHandshake`。控制断开时使旧会话失效并丢弃旧解析器；EOF 调用 `Complete()` 记录残帧。
2. `decoder.Feed(chunk)` 返回有效帧或结构诊断。只有校验 / 长度正确的完整帧进入语义解析；帧的 `Type` / `Sequence` / `Payload` 都保留。
3. 对合法 Table 1 / 2 数据帧生成互补序号 ACK，包括未知命令；无效序号不调用 ACK helper。帧有效不等于载荷已识别，未知消息保留供 SC-7 诊断。
4. `handshake.CurrentQuery` 是当前需要的纯字节查询。SC-6 负责发送与 ACK 时限、序号分配、发送次数和响应时限；Core 没有发送网络数据，也不自动循环重发。
5. `handshake.Receive(session, frame)` 只在会话、表、响应命令和 inquiredType 与当前查询匹配时推进。ACK / 通知 / 重复响应 / 未知 / 损坏载荷不完成查询；`Parsed` 与 `Diagnostic` 可记录。单个 reducer 按接收顺序调用，不跨线程并发修改。
6. Ready 后将身份、功能表及报告来源交给 Application。真实业务参数解码、确认回读、ACK / 重试队列由后续任务实现；不能用这个离线 reducer 宣称系统蓝牙或实机写入已可用。

## 时序、失效与日志

每个物理 LinkId 创建 decoder、协议族、发送序号和有界串行队列。查询等待 ACK 和匹配的合法响应，允许响应先到。设置命令的 ACK-only 成功仅指投递，Application 随后回读才确认设置。有效表帧包括未知消息均 ACK，最后完整帧按表 / 序号 / 载荷去重；畸形载荷之后的合法消息不被误去重。

收到线上的真实通知只更新共用确认值，不把草稿当成设备值。参数回读若早于较新的参数通知，不覆盖通知；可用性通知与参数具有独立顺序。正在变化的参数不确认成功，保留最后稳定值并暂停可写路径。新意图合并到同一完整 NCASM 参数，旧意图不会刷新最新成功反馈。

送出前取消不损坏会话；送出后取消、超时或写入失败隔离协议上下文，必须手动断开 / 重连，不自动重发。候选每次手动连接最多 1 次 socket 尝试，连接 / 环境等待 8 秒，各命令 ACK / 回读总截止 5 秒。启动只发现已配对设备，不自动连控制通道。完整握手及 WF 参数读取完成后才返回连接成功。

`JsonLineDiagnosticLog` 自动保存时间、连接、握手、发送 / ACK / 响应、请求关联、目标 / 确认值、代次、接收顺序、通知、错误码和正常退出。逐条刷新，退出等待队列并 Flush；队列 2048、单次四个约 2 MiB 轮转段，各次运行保留。失败 / 丢弃计数显示在 UI。日志不保存蓝牙地址、系统设备 ID、自定义名称、能力唯一标识或完整载荷。尚无 Windows 系统事件自动采集和完整原始字节导出。

- 实机、Simulation、Replay 分别写入来源标签。模拟 UI 横幅持续标示“离线模拟”；回放窗口标示“离线事件时间线”，不会连接设备或发送命令。
- 每次运行最多 4 个 JSONL 轮转段；每段可设 1–8 MiB，默认 2 MiB；保留运行次数可设 1–100，默认 10。设置保存在 `%LOCALAPPDATA%\SonyConnect\diagnostics.json`。
- 保留策略仅识别本程序命名的日志文件，并仅清理具有 `log-end` 的已正常结束运行；活动、异常结束及不匹配命名的文件保留。单次运行容量上限为 4 × 单段大小，默认 8 MiB。
- “导出脱敏诊断包”生成 `.scdiag` ZIP。导出只复制明确允许的诊断字段，删除未知字段，处理蓝牙地址及 12 位设备标识；不包含原始协议载荷、Windows 设备 ID 或自定义名称。
- “回放诊断包”读取本程序 schema 的事件时间线，显示时间、来源、事件和 RequestId 等信息。它重现的是已记录的脱敏事件，不重放协议字节，也不能作为耳机功能或硬件兼容性证明。

## 使用

启动 SonyConnect 后，在“诊断日志”区域设置每段容量与保留运行数并点击“保存并应用”；可导出 `.scdiag` 包并在同一区域打开回放。无设备时可使用 `--simulate`，横幅和每条日志都会标明 Simulation。设备模式的硬件验证状态仍以 WF / WH、固件及单独实测记录为准。
